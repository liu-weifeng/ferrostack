# 资源规划页面原型（独立 demo）

`docs/resource-planning.md` §5 页面设计的可交互原型。**独立于 Web 控制台**：
单个 HTML 文件、纯原生 JS、零依赖、不需要构建，也不连任何后端——所有数据是内置
的模拟数据（16 核 / 2 NUMA / 256 GB 主机 + 6 台示例 VM），只用来演示页面布局与操作逻辑。

## 运行

```bash
# 直接用浏览器打开即可
xdg-open demo/resource-plan/index.html

# 或起个静态服务（任选）
python3 -m http.server -d demo/resource-plan 8099   # → http://127.0.0.1:8099/
```

右下角 🌓 按钮切换亮/暗主题（默认跟随系统）。字体从 Google Fonts 加载，离线时自动回退系统字体。

## 能操作什么

### 主机全局视图（默认页）

| 区域 | 查看模式 | 编辑模式（点工具栏「编辑」） |
|---|---|---|
| CPU 归户条 | 内核 / 系统服务 / 虚拟化系统 / SPDK / 虚拟机 / 空闲；点「虚拟化系统」展开到服务级 | — |
| CPU 拓扑板 | 按 NUMA 节点排列，物理核以 HT 线程对成组；颜色 = 池归属，底部填充 = 利用率（2.5 s 模拟刷新）；SPDK 核虚线框，独占核带 VM 名；图例下方「浮动 VM」汇总条（台数 / Σ vCPU / 共享池可用线程 / 超分比） | 拖核 → 底部池图例改归属（可先点选多核批量拖）；把右栏 VM 行拖到核心 → 独占绑定（浮动 VM 的内存随之改绑该节点） |
| 内存与大页板 | 每节点分段条：内核·其它 / OS 预留 / 虚拟化预留 / 2M 大页 / 1G 大页 / 绑定 VM 已用 / 浮动 VM 实测落点（斜纹）/ 余量 | 拖分段间手柄调整预留与大页；1G 大页改动自动标 ⟳ 需重启 |
| 内存分层板 | 压力计 + 下刷/回血水位线；逐 VM 常驻/换出条；后端盘水位 | 拖水位线刻度（下刷线必须低于回血线） |
| SPDK 预留板 | 隔离核、候选核上限（启动档声明）、reactor 活跃/上限、IRQ/workqueue 驱离状态、分区回读与在线加核顺序 | 勾选低抖动启动档（标 ⟳ 需重启）；给 SPDK 加核 = 把核拖到 SPDK 图例，超过候选核上限会被校验拦下 |
| 自动放置卡（§3.10） | 当前**负载档位**（宽裕 / 适中 / 紧张，含 L 指数与 oc、内存用量、PSI、独占核供需）与该档的目标形态；固定 / 自动 VM 台数；三个阈值；每节点 oc / 共享线程 / 空闲独占核 / 空闲内存；进行中迁移的进度条；**本拍动作**（求解目标 vs 当前，标「免费 / 有成本」）；最近决策列表 | 编辑态可改开关 / 模式 / 阈值（进变更清单）；**负载模拟 低·中·高** 切换运行中的 VM 集合观察档位变化；「执行一拍」真正把动作施加到放置上（免费动作全做，换节点最多一台并启动迁移进度）；「仅出建议」只记录不执行 |
| 右栏 | VM 列表：放置等级徽标 **A 独占 / B 节点共享 / C 浮动 / V 显式 vNUMA** + 类别（自动 / 🔒固定）+ 迁移中标记 + 放置模式 / 后端 / 内存分层状态 | 变更清单：每条带 即时 / 热调 / ⟳重启 徽标，可逐条撤销；「校验」跑规则，「应用」模拟异步任务并弹待重启横幅 |

校验规则（会阻断应用）：池最小核数、缩池撞上独占绑定、大页缩到在用量以下、
VM 池内存预算不足、水位线顺序错误、共享池被抽空 / 低于浮动 VM 最大规格、
绑定单节点的 VM 所在节点共享池无核、SPDK 池超过候选核上限、独占超分上限不低于释放超分；
浮动 vCPU 超分 >4× 与单节点共享池为空只给警告。

**固定 VM 与自动 VM**：用户在界面手动指定了 CPU 绑定 / NUMA / 内存预留的 VM 是**固定**的
（右栏 🔒 标记），控制器把它们当成不可移动的约束——占用的核、绑定节点上的内存和
`memory.min` 预留先扣除，求解只在剩余资源上做；显式 vNUMA 与 1G 大页后端强制固定。
其余 VM 是**自动**的，控制器按当前负载档位在 A / B / C 三种形态间在线求最优：

- **宽裕**：自动 VM 全部 A（独占绑核 + 绑节点），按节点装箱。
- **适中**：A/B 混合，优先级高的保留独占，其余绑节点共享。
- **紧张**：释放全部独占核，B/C 均衡超分，内存放不下的允许浮动跨节点。

用「负载模拟」切到高档再点几次「执行一拍」，可以看到独占核被逐步释放、VM 在两节点间
重新装箱；切回低档再执行，独占绑定会重新升回来。固定的两台（`db-core-01` 显式 vNUMA、
`batch-02` 用户锁定的浮动 + 6G 预留）全程不动。

### 单 VM 视图（点右栏任意 VM 行）

- **CPU 放置**：共享 / 独占两种模式。独占模式下把 vCPU chip 拖到虚拟机池的线程格做 1:1 绑定，
  被其他 VM 占用的线程置灰拒绝落点；提供「自动绑定 N0 / N1」与清空。运行中 VM 的绑定标「热调」。
- **NUMA**：三态——不绑定（浮动，默认；显示实测跨节点分布与落地参数）/ 绑定单节点
  （选节点，显示对应 `host-nodes` 参数与节点剩余容量）/ 显式 vNUMA
  （编辑各 vnode 的 vCPU / 内存 / 宿主节点，Σ 必须等于 VM 总量）。
  共享模式下会列出当前实际可调度的线程范围；独占绑核但内存不绑 NUMA 会给跨节点访存警告。
- **内存后端**：匿名 / 共享 memfd / 大页 三选一，互斥关系按设计矩阵体现——
  挂分布式存储盘的 VM 不能选匿名；内存分层开关只在匿名后端可用。
- 底部「生效方式」卡区分 热调 / 下次启动生效 / 立即。「保存」写回到主机视图（若正在编辑主机规划，则并入当前草稿）。
- **固定 / 自动**：顶部横幅显示该 VM 是由控制器自动放置（含当前等级与档位）还是用户固定；可「改为固定」或
  「交回自动放置」；固定后可填 `memory.min` 内存预留（计入主机内存条的「固定 VM 预留」）。
  手动修改任何放置字段并保存会自动转为固定；显式 vNUMA 与 1G 大页后端强制固定。
- **在线 NUMA 迁移**：运行中的 VM 切到「绑定单节点」并换一个节点保存，就会走在线流程——
  面板显示按 `numa_maps` 实测的两节点内存分布条、五步流程指示（准入 → AllowedCPUs 切 vCPU（即时）→
  AllowedMemoryNodes 触发内核后台迁页 → 等待 ≥95% → 落库）和实时进度。
  准入会拦截：1G 大页 VM 不支持在线换节点、目标节点空闲内存不足、主机已有迁移进行中（同时最多一个）。

## 与设计文档的对应

- 页面布局、池划分、三种内存后端互斥、生效时机标注：`docs/resource-planning.md` §5 / §3.4。

  `index.html` 顶部 `:root` 里的 `--p-*` / `--hp*` token。

  `resource-plan`，应用走 TaskManager 异步任务（见设计文档 §4.2 / §5.4）。
