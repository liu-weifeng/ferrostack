§0 摘要 · 选型决策

一句话：以 cgroup v2 cpuset 分区为唯一基础机制做运行时可调的 CPU/内存池化， 每台 VM 落入独立 systemd scope；隔离、预留、大页、NUMA、SPDK、内存分层统一收进 一份 per-host「资源规划（resource plan）」，由宿主机代理幂等对账落地，前端在 主机详情新增「资源规划」tab 做图形化展示与拖拽编辑。

问题决策理由
CPU 隔离用什么cgroup v2 cpuset 分区（cpuset.cpus.partition），不以 isolcpus 为基础机制isolcpus 需重启、静态、全有全无；内核 6.7 的 isolated 分区在运行时提供等效隔离（脱离调度域、无负载均衡），正好支撑「拖拽即生效」
SPDK 轮询核cpuset isolated 分区 + 可迁移 IRQ 驱离 + unbound workqueue cpumask 排除；managed IRQ（NVMe/mlx5）只能靠 isolcpus=managed_irq，与 nohz_full 一起归入「低抖动启动档」（标「需重启」）轮询线程要独占核、免时钟/中断干扰；isolated 分区覆盖 90% 需求，极致低抖动才需要 boot profile
per-VM 资源边界systemd transient scope：vm-<uuid>.scope 挂 machine.slice，QEMU 经 systemd-run --scope 在 exec 之前就落入 scope目前全部 QEMU 挤在虚拟机监控服务 unit 的 cgroup 里（KillMode=process 的副作用），无法逐 VM 计量/限额；先起进程再搬会让 prealloc 的内存与大页永久计费到旧 cgroup（§3.3）；scope 顺带让 QEMU 生命周期独立于虚拟机监控服务重启
vCPU 绑定scope 级 cpuset 定池 + QMP query-cpus-fast 拿线程 id 后 sched_setaffinity 做 1:1 独占绑定池归属用 cgroup（可整体挪），精确 pin 用线程亲和性；两层正交
内存预留memory.min 保护 OS / 虚拟化服务 /（P4）VM 热集；machine.slice 用 memory.high 做 VM 池软预算，再以 memory.max 兜底 + 每 scope memory.oom.group=1min 只保护已驻留页、不预扣内存；VM 匿名页在无 swap 主机上不可回收，high 只能节流不能阻止超限，没有 max 时预留会被吃穿、最后是全局 OOM 随机杀。max 取"MemTotal − 各项预留 − 大页 − 余量"，只在主机本来就要 OOM 的点上把代价收敛成"杀一台 VM"
大页per-NUMA sysfs 运行时分配（2M 常态可行）；1G 走启动参数/开机早期预留，UI 标「需重启生效」；hugetlb cgroup 圈 SPDK 与 VM 的用量1G 页在内存碎片化后运行时分配基本必失败
VM NUMA 落位三态：浮动（默认，不绑核不绑 NUMA，跑在未预留资源上）/ 绑定单节点（只用 scope 的 cpuset.mems，QEMU 不带 host-nodes）/ 显式 vNUMA（-numa node,memdev，per-memdev host-nodes）与现状兼容（今天所有 VM 都是浮动）；需要亲和的 VM 再显式绑
动态自动绑定 / 在线调整主机级放置控制器（§3.10）：启动时按余量给 A 独占 / B 节点共享 / C 浮动；运行中靠 scope 的 AllowedCPUs（即时）+ sched_setaffinity（即时）+ AllowedMemoryNodes（cgroup v2 写 cpuset.mems 触发内核异步迁页）在线搬 vCPU 与内存不需 QEMU/guest 配合、6.7 原生；与 libvirt numatune --live 同机制；用户显式放置永不被动
内存分层关系仅「匿名内存」后端模式的 VM 可开启（现状约束）；主机总控的水位线/预算改从 resource plan 读取并在 UI 暴露内存分层强制 4K 匿名页，与大页、vhost-user（分布式存储/SPDK）共享内存互斥；总控现在的阈值是环境变量常量，应归入规划统一管理
前端形态主机详情新 tab「资源规划」：查看模式实时叠加用量，编辑模式草稿 → 校验 → 异步任务应用沿用既有 TaskManager / WS / i18n 约定
数据链路配置走新 REST（plan API + 本地缓存对账）；用量走既有宿主机代理 exporter → 时序库 → 管理服务指标代理监控链路已建成，补 collector 即可；顺带落地 vm-direct-metrics-design.md 里搁置的 per-VM cgroup 直采

§1 目标与非目标

目标

  • 隔离：OS（内核 + 系统服务）、虚拟化服务（管理服务/宿主机代理/虚拟机监控服务/分布式存储/数据库/Web 网关等）、SPDK、虚拟机四类负载互不侵占 CPU；SPDK 核完全独占。
  • 预留：OS 与虚拟化服务的内存有硬保障（不被 VM 压力回收挤死）；大页按 NUMA 节点、按页大小（2M/1G）定量预留；SPDK 的核与大页单独圈占。
  • 可视：主机 NUMA 拓扑、每个逻辑 CPU 的池归属与实时利用率、每 NUMA 节点内存的分段构成（内核/预留/大页/VM/空闲）、每台 VM 的占用与放置、内存分层常驻/换出/后端盘用量，全部图形化。
  • 可拖拽：核心 → 池、VM → 核（独占绑定）、内存段边界手柄，都可拖拽调整；所有操作有非拖拽等价入口（右键菜单/输入框）。
  • 可对账：规划持久化于 DB + 主机本地缓存，重启后由宿主机代理先于 VM 启动幂等重放。

非目标（本期不做）

  • 集群级调度联动（放置时感知各 host 池余量）——plan 是 per-host 对象，center 侧先做逐主机入口，聚合视图后续。
  • SPDK 本体的部署编排（bdev/vhost target 配置）——本期只做资源预留与展示，把核和大页圈出来。
  • CPU 时间片精细 QoS（cpu.max 配额、实时调度类）——先池化，配额留作后续旋钮。

§2 资源模型

2.1 CPU：五类池归属

主机的每个逻辑 CPU（含超线程）在任一时刻属于且仅属于一个池。池即 cgroup 顶层 slice 的 cpuset（§3.2）：

池承载隔离强度默认规模建议
system（OS）内核杂务、sshd、systemd、journald 等 system.slice/user.slice/init.scope软边界（cpuset 圈定，不隔离调度域）≥2C（≥64C 主机取 4C）
virt（虚拟化服务）virt.slice：管理服务 / 宿主机代理 / 虚拟机监控服务 / 集群服务 / 分布式存储守护 / 数据库 / Web 网关 / 控制台代理 / 虚拟交换机用户态软边界2–4C，跑分布式存储 OSD 的节点加大
spdkspdk.slice（reactor 轮询线程）isolated 分区：脱离调度域 + IRQ 驱离按 vhost 目标带宽定，1–4C 起步；未部署 SPDK 时池可为空
vm-shared（VM 共享 = 未预留资源）machine.slice 下未独占的 VM scope。它是残差池：system / virt / spdk / dedicated 之外的全部核自动归此，不需要（也不能）单独"分配"——把核从别的池释放即回到这里软边界 + per-VM cpu.weight其余全部
vm-dedicated（VM 独占）被某台 VM 1:1 绑定的核（vCPU 线程 pin），从 vm-shared 中划出逻辑独占（同池内不共享）；可选升级为 isolated 子分区（前提：machine.slice 自身先写 cpuset.cpus.partition=root 成为有效分区根，子 scope 才能写 isolated）按需
浮动 VM（floating）：不绑核、不绑 NUMA 的虚拟机——即今天系统里所有 VM 的形态。 它们与做了预留/绑定的 VM 长期共存：调度范围 = vm-shared 全部线程（两节点）， 内存来自各节点扣除内核·预留·大页后的 VM 池余量，落点由内核 first-touch 决定、 可能跨节点。规划页面必须把这一类单独呈现（台数 / Σ vCPU / 共享池线程 / 超分比、 内存条上的实测跨节点分布），缩共享池时按它们的规格和超分比校验（§4.4）。
超线程配对约束：分池以物理核为最小拖拽单元（一对 HT 同进同出）。跨池 共享同一物理核的两个 HT 会让「隔离」名存实亡；SPDK/独占池尤其如此。UI 上 HT 成对渲染，整核拖动。

§3 后台实现

3.1 选型：cgroup v2 分区，而不是 isolcpus

isolcpus / nohz_full（启动参数）cgroup v2 cpuset 分区（本方案）
调整改 grub + 重启运行时写 cgroupfs，秒级生效 → 支撑拖拽
隔离强度彻底（连 unbound kthread 都躲开，nohz_full 免 tick）isolated 分区 = 脱离调度域、无负载均衡（6.1+；6.7 完整）；per-cpu kthread 仍在，tick 仍在
粒度整机一份静态清单逐 slice/scope，层级化，可与 weight/quota 组合
与 systemd无关AllowedCPUs=/AllowedMemoryNodes= 原生映射 cpuset

结论：基础机制只用 cgroup v2。SPDK 池用 isolated 分区；对极致低抖动需求提供 可选「低抖动启动档」（nohz_full=<spdk cpus> rcu_nocbs=… irqaffinity=…，由 主机初始化写 grub drop-in，UI 标「需重启」）。

  • isolated 分区的前提：内核要求分区的 CPU 不与已配置 cpuset.cpus 的兄弟 cgroup 重叠（未设值的兄弟不构成冲突）。给所有顶层 slice（含 init.scope/user.slice） 显式设 AllowedCPUs 是充分条件而非内核要求，「全量池化」天然满足；反过来对账时 要扫根下全部子 cgroup（含临时 scope、容器运行时建的组），不能只查已知的几个 slice。 写入失败不返回 EINVAL：写成功但回读 cpuset.cpus.partition 为 isolated invalid (<原因>)， 原因字符串可直接上报（如 Cpu list in cpuset.cpus not exclusive）。
  • 共享池变更的扇出：浮动（C 级）scope 挂 machine-shared.slice 且不设自己的 AllowedCPUs，直接继承，缩共享池一次写入即可；A/B 级 scope 仍逐个显式设。
  • memory.min 的层级约束：cgroup v2 的 min 保护按层级分配——子 scope 的 memory.min 只有在父 machine.slice 自身设了 ≥ Σ 子项的 memory.min 时才有效。 控制器在增删任一 scope 的 min 时同步改写 machine.slice 的 min（§3.7 P4 依赖此）。
  • 归并系统服务：数据库/Web 网关等属于虚拟化平台的服务用 drop-in Slice=virt.slice 归入 virt 池——「虚拟化系统占用」在页面上才是一条完整、 诚实的曲线。
  • 下发方式：systemctl set-property（运行时 + 自动落 drop-in 持久化）设 AllowedCPUs / memory.\*；cpuset.cpus.partition、hugetlb 上限等 systemd 不覆盖 的属性由 agent 直写 cgroupfs，并由开机对账单元重放（§3.9）。

3.3 per-VM scope：QEMU 从虚拟机监控服务的 cgroup 里搬出来

现状：虚拟机监控服务拉起 QEMU（subprocess），QEMU 全部落在 虚拟机监控服务 unit 的 cgroup；服务重启靠 KillMode=process 保命。后果：无法逐 VM 计量 （memory.current/cpu.stat/PSI 全是糊的）、无法逐 VM 限额、也无法把 VM 整体挪池。

改造（虚拟机监控服务 launch_vm）：

  1. 在 exec 之前就落入 scope：`systemd-run --scope --unit=vm-<uuid> --slice=machine.slice（C 级为 machine-shared.slice） -p Delegate=yes -p CPUWeight=… [-p AllowedCPUs=… -p AllowedMemoryNodes=… -p MemoryMin=…] -p ManagedOOMPreference=none -- setsid --fork qemu … -S`。 不能「先起进程再 StartTransientUnit 搬 pid」：模式 B/C 的 prealloc=on 在 -S 暂停点之前就完成全部内存分配，搬 pid 不搬已计费的页，memory.current 会永久偏低、hugetlb.*.max 对这台 VM 完全失效——这不是一次性的存量问题， 每次开机都会发生。虚拟机监控服务今天已是 setsid --fork 双 fork 拉起， 父子关系本就断开，systemd-run 包一层不改变任何既有语义；
  2. 虚拟机监控服务拿到的 Popen 句柄是 setsid/systemd-run 自身，**真实 QEMU pid 从 pidfile（-pidfile）或 QMP 取**，后续 numa_maps / 线程 id 一律用该 pid；
  3. 独占 VM 经 QMP query-cpus-fast 取 vCPU 线程 id，逐线程 sched_setaffinity 1:1 绑核；scope 上再写 memory.oom.group=1（systemd 不覆盖，直写 cgroupfs）；
  4. QMP cont 放行。
  5. 模式 B 强制 prealloc=on：共享 memfd 的 shmem 页计费到首次触碰者，若分布式 存储后端先于 QEMU 触碰，页会记到 virt.slice、吃掉虚拟化预留。
  6. 顺带收益：QEMU 不再住 service cgroup，虚拟机监控服务/宿主机代理重启天然不波及 VM， KillMode=process 从「保命 hack」降级为双保险。
  7. 存量迁移：升级后对账把运行中 QEMU 的 pid 写入新建 scope 即可（cgroup v2 允许 迁移）；注意已计费的匿名页仍挂在旧 cgroup，memory.current 要到页面重新 fault 后才逐步归位——统计初期偏低是预期行为，标注即可，或选择「下次 VM 重启时生效」。
  8. emulator/iothread 分离（P2 可选）：scope 开 Delegate=yes 后建 threaded 子组 vcpu/ 与 emulator/，独占 VM 的模拟器线程可留在共享池，进一步降低独占核抖动。

3.4 内存预留与 VM 池预算

# 预算不等式（per host，规划器校验；内核不强制，见下）：
OS 预留(memory.min@system.slice)
 + 虚拟化服务预留(memory.min@virt.slice)
 + Σ 大页池(2M+1G，含 SPDK 圈占)
 + VM 池预算(memory.high@machine.slice)
 ≤ MemTotal − 内核残差观测峰值 − 安全余量(≥ 4% MemTotal)

memory.max@machine.slice = MemTotal − OS 预留 − 虚拟化服务预留 − Σ 大页池 − 安全余量
  • memory.min 是「预留」的落地：VM 压力触发全局回收时，受保护 slice 的页不被 扫描。但 min 不预扣内存，只保护已驻留页：系统服务事后增长的部分要从别处回收， 而模式 A（未开分层）与模式 B 的匿名/shmem 页在无 swap 主机上不可回收， memory.high 此时只能节流、不能阻止超限，最后是全局 OOM 随机杀进程——所以上面的 预算式只是校验器约定，内核并不替你守住它。前提：根上 subtree_control 启用 memory 控制器（systemd 默认满足，agent 对账时校验）。
  • 内核残差是实测且波动的量，校验器按「Σ 规划项 ≤ MemTotal − 观测残差峰值 − 余量」 实现（残差峰值取 exporter 近 7 天最大值，首次取当前值 × 1.2）。
  • VM 池：memory.high 做软预算（顶到 high 触发直接回收 + 节流，给内存分层总控留 下刷窗口），再以 memory.max 兜底——取「MemTotal − 各项预留 − 大页 − 余量」， 它只在主机本来就要 OOM 的那个点上生效，配合每个 scope memory.oom.group=1，把 最坏情况从「随机杀进程」收敛成「整台杀一个 VM」（杀谁由 memory.oom.group + oom_score_adj 按优先级映射决定）。
  • hugetlb 不计入 memory.current：6.7 上 memory_hugetlb_accounting 挂载选项 默认关闭，模式 C 的主内存走 hugetlb.* 控制器、不进 memory 控制器——VM 池校验与 memory.high/max 只算模式 C VM 的 QEMU overhead，其主内存在大页池段核算。
  • VM 池预算校验规则：Σ(运行中非内存分层 VM 内存 × (1+overhead)，模式 C 只算 overhead) ≤ 预算； 内存分层 VM 按 min-resident 折算下限、按全额折算上限，两条线都在 UI 显示 （「保证线 / 超分线」）。QEMU per-VM overhead 取 3% + 300MB 经验值，进规划器常量。

3.5 大页管理

  • 分配：写 /sys/devices/system/node/node<N>/hugepages/hugepages-{2048kB,1048576kB}/nr_hugepages， 按节点精确投放。2M 运行时通常可满足（失败时 agent 先 compact_memory 重试一次）； 1G 运行时分配在碎片化后基本必失败——策略：规划里记目标值，agent 尝试运行时 分配，不足额则该项标「需重启」，由开机早期单元（resource-plan.service， §3.9）在 boot 早期补齐，兜底方案才是 grub hugepagesz=1G hugepages=N。
  • 圈占：SPDK 与 VM 共用 HugeTLB 池但通过 hugetlb.2MB.max / hugetlb.1GB.max 在 spdk.slice 与 machine.slice 上互相设限，防一方吃光另一方的预留。SPDK 走 mmap 预留，.max 与 .rsvd.max 要一起设（前者管 fault 时的计费，后者管 mmap 时的预留计费）。
  • 控制器要手工开：systemd 不会在根 cgroup.subtree_control 里启用 hugetlb， 开机对账单元（§3.9）负责写 +hugetlb（根与 machine.slice/spdk.slice 逐层）， agent 对账时校验。
  • 消费：模式 C VM 用 memory-backend-memfd,hugetlb=on,hugetlbsize=2M|1G,share=on,prealloc=on （免 hugetlbfs 挂载点管理）；SPDK 用其自带 --huge-dir/--mem-size。

3.6 NUMA 落位

  • 拓扑采集：宿主机代理新增 scan_cpu_topology（并入 scan_device 结果树）： /sys/devices/system/cpu/cpu*/topology/*（socket/core/thread 配对）+ /sys/devices/system/node/node*/（cpulist、meminfo、hugepages、distance 矩阵）。 落管理服务新表（§4.1），供拓扑图渲染。
  • 浮动（默认，numa_mode=none）：不绑 NUMA。scope AllowedCPUs=<vm-shared>、 AllowedMemoryNodes=<全部节点>，QEMU 不带 host-nodes；内存 first-touch，实际分布 由 numastat -p <qemu pid>（或 /proc/<pid>/numa_maps 聚合）采集后展示。与现状零差异， 升级后老 VM 自动落入此态。浮动 ↔ 绑定单节点可热调，但注意语义差别：只改 AllowedCPUs 不迁页；改 AllowedMemoryNodes（= cpuset.mems）在 cgroup v2 下 必然触发全量异步迁页（memory_migrate 恒开，§3.10.4），几十 GB 的 VM 会在 后台搬几十秒到几分钟——所以「绑定单节点」的热调必须走 §3.10.5 的标准流程并在 UI 显示进度，不能当成零成本操作。
  • 绑定单节点（numa_mode=node）：放置器选「绑定池核数与空闲内存都放得下」的最空节点； 只用 scope 的 AllowedMemoryNodes=N（cpuset.mems），QEMU 不带 host-nodes—— 两套机制叠加是重复约束，换节点时还要依赖内核对 MPOL_BIND 做 nodes_remap 才能跟上， 多一层验证负担；host-nodes 只留给 vNUMA 的 per-memdev。vCPU 限该节点池内核（共享） 或 1:1 绑定（独占）。 独占绑核而内存仍浮动是允许但要警告的组合（跨节点访存）。
  • 跨节点 VM（显式 vNUMA，numa_mode=vnuma）：vm_config.numa 声明 vnode 列表（每 vnode：vcpus、 内存、host-node），拼 -numa node,nodeid=i,cpus=…,memdev=mi，guest 内看到与宿主 对齐的拓扑。页面 VM 详情画 vNUMA→host node 的映射关系。
  • 降级：单 NUMA 主机（现有 lab 的 E5-26xx v3 单路）一切照常，页面只渲染一个节点组。

3.7 内存分层融合

  • 准入：mem_backend=anon 才可开内存分层（既有分布式存储盘互斥校验推广为三模式 矩阵校验）。
  • 预算联动（P4）：总控内存分层总控模块 现在用 三个环境变量常量（空闲低/高水位、PSI 阈值）算主机压力。改为 从本地 plan 缓存读：压力 = max(PSI 项, 预算项)，预算项 = VM 池 memory.current 相对 memory.high 的挤占度。下刷/回血两条水位线成为 plan 字段，UI 可调 （内存分层面板上的两个刻度，§5.3）。
  • 热集保护（P4 可选）：总控把每台 内存分层 VM 的 scope memory.min 同步为 min-resident-mb + overhead，防 VM 池整体回收把热集也挤掉。同时必须把 machine.slice 的 memory.min 维持为 Σ 子 scope min（§3.2），否则子项的 min 在层级分配下为 0、保护无效。
  • 展示数据：全部来自既有 内存分层查询接口（经虚拟机监控服务）： `resident-bytes / swapped-bytes / backing-total|used / evict-mbps / swapin-faults / psi-some-avg10`，聚合进 exporter（§6）。

3.8 SPDK 预留

  • 本期交付：plan 中的 spdk 块（核列表 + per-node 大页额度）→ agent 建 spdk.slice、写 isolated 分区、按额度校验大页池、驱离 IRQ 与 unbound workqueue：
    • 现存可迁移 IRQ 逐个改写 smp_affinity_list；irqbalance 未必安装，agent 不依赖 它，装了才补 IRQBALANCE_BANNED_CPULIST drop-in 防它改回来；
    • 6.7 的 isolated 分区不会把 CPU 从 unbound workqueue 的 cpumask 里摘掉 （6.9 才有），agent 同时写 /sys/devices/virtual/workqueue/cpumask 排除 spdk 核；
    • NVMe、mlx5 等 managed IRQ 无法通过 smp_affinity_list 改绑（返回 EIO）， 只能靠 isolcpus=managed_irq,<spdk cpus> 启动参数——归入「低抖动启动档」。
  • 后续接线：SPDK vhost target 以 spdk-vhost.service（Slice=spdk.slice）部署， reactor mask = 池核；被服务 VM 走模式 C；reactor 是 100% 轮询，利用率图对 spdk 池 改显示「占用/预留」而非 busy%（接 SPDK 自身 stats 后再显示有效利用率）。

SPDK 隔离方式的结论（cgroup 分区，而非 isolcpus）：

  • SPDK 不需要"绝对隔离"。reactor 是用户态轮询线程，真正怕的是三件事：别的任务 抢核、IRQ 打断、HT 兄弟核干扰。isolated 分区（脱离调度域、独占）+ 整核成对划入 + IRQ 驱离已覆盖这三件。残余只有周期 tick 与 per-CPU 内核线程：每核每秒数百次、每次 约 1–2 µs，占用 < 0.2%、抖动微秒级，对几十微秒量级的 IO 路径没有实际影响。
  • isolcpus 做不到在线增减：它是启动参数，改一次重启一次，且内核文档已标为 Deprecated、建议改用 cpuset；在"调度域隔离"这一层 isolated 分区与 isolcpus=domain 是同一件事，差别只剩 nohz_full / rcu_nocbs / managed_irq 这些只能启动时设的项——归入可选的「低抖动启动档」，并且只声明 SPDK 候选核上限 （如最多 8 核），之后实际给多少核仍由 cgroup 在上限内动态决定；候选核暂时跑 VM 时 多付少量 context-tracking 开销，故上限不宜划大。
  • 在线给 SPDK 加核（cgroup 层可行），固定顺序：从 machine.slice 的 cpuset 拿掉这对 HT（VM 线程自动迁走）→ 写进 spdk.slice 的 cpuset（分区保持 isolated）→ 回读 cpuset.cpus.partition 确认不是 isolated invalid → 改写现存 IRQ 亲和性 + irqbalance 禁用列表 + workqueue cpumask。managed IRQ 只在本核发起 IO 时才触发，核上只有 SPDK 时 不会响；SPDK 自己接管的 NVMe 走 vfio，没有内核 IRQ。
  • 真正的限制在 SPDK 进程层：reactor 核集由启动时的 core mask 固定，运行中不能新增 reactor。两种做法：① 推荐——SPDK 启动时 reactor mask 覆盖候选核上限，开 dynamic 调度器让线程只落在需要的 reactor 上，cgroup 只把当前实际需要的核给 spdk.slice， "加核" = cgroup 加核 + 调度器放开对应 reactor（需验证所用版本下空闲 reactor 是否真正 停止轮询，否则被内核挪到允许核上空转）；② 兜底——改 core mask 重启 vhost target， 依赖 inflight-shmfd 重连 + QEMU chardev reconnect，客户机不重启、仅短暂 IO 停顿。

IRQ 与内核线程的诚实口径：

  • SPDK/独占池核通过 irqbalance banned + 显式 affinity 驱离可迁移 IRQ；per-CPU kthread（ksoftirqd 等）与 timer tick 无法用 cgroup 移走——这是 isolated 分区与 isolcpus 的真实差距，UI 的池 tooltip 里注明「残余内核活动 < ~1%」。
  • vhost-net 等内核线程不入任何 cgroup，其 CPU 计入「内核/其它」段；后续可按 VM 把 vhost 线程 affinity 跟随其池（增强项）。

3.10 动态自动绑定与在线调整（放置控制器）

目标：用户在界面手动指定了 CPU 绑定 / NUMA / 内存预留的 VM 是「固定」的，永远不被 自动改动；其余全部 VM 由控制器按主机当前负载在线求最优绑定——负载低时每台都拿到 独占绑核 + 绑节点，VM 变多时在线降级、跨节点再平衡，VM 减少时再升回去。 所有 调整都在线完成（vCPU 即时、内存后台迁页，§3.10.4），不重启 VM。

3.10.1 两类 VM：固定与自动

类别谁决定内容控制器怎么对待
固定（placement_source=manual）用户在 VM 视图显式设置，或点「锁定」CPU：独占核集合 / 绑定节点 / 浮动；内存：绑定节点或 vNUMA、mem_reserved_mb（scope memory.min）；后端模式不可移动的约束：它占的独占核、绑定节点上的内存与预留先从可用资源中扣除，求解只在剩余资源上进行
自动（placement_source=auto，默认）控制器同上三个维度，由求解器在线赋值每拍重新求最优，变更走在线原语

强制固定（不给自动）的三类：显式 vNUMA（缺 per-memdev 迁移原语）、vfio 直通（页被 pin 不可迁）、1G 大页后端（迁移慢且依赖目标节点空闲 1G 页）。用户改动自动 VM 的任一 放置字段并保存 = 转为固定；「交回自动」则下一拍重新求解。固定 VM 的内存预留 memory.min 同时进入 §3.4 的预算恒等式，UI 在内存条上以实色标出。

自动 VM 的可能形态就是三个等级：

等级含义对应字段（§4.1）
A · 独占vCPU 1:1 绑物理线程 + 内存绑同一节点cpu_placement=dedicated, numa_mode=node
B · 节点共享不绑核，但限定在一个节点的共享池内 + 内存绑该节点，cpu.weight 按优先级cpu_placement=shared, numa_mode=node
C · 浮动不绑核不绑 NUMA（§3.6 默认态）cpu_placement=shared, numa_mode=none

3.10.2 「最优」的定义：目标函数 + 负载档位

目标函数（对自动 VM 集合求放置 P）：

Cost(P) = Σ_vm [ w_remote · remote_mem_ratio(vm)          // 跨节点访存比例（numastat 实测 / 目标为 0）
              + w_cont   · contention(vm) ]                 // 所在共享域的超分比 oc（独占 = 0）
        + w_bal · |load(N0) − load(N1)|                     // 节点间 vCPU 与内存用量不均衡
        + w_move · Σ_{vm 变更} move_cost(vm)                // 常驻内存 / 迁页带宽 + 冷却惩罚（滞回来源）
约束：固定 VM 不动；每节点 Σ内存 ≤ VM 池预算；独占核两两不交且 HT 成对；
      绑定后节点剩余共享线程 ≥ min_shared_threads；池边界 = plan 的共享池

move_cost 是避免抖动的核心：一个变更只有在「预计收益 ≥ 搬动成本 + 冷却惩罚」时才 执行，因此负载短暂波动不会引发来回搬。权重有默认值，不在 UI 暴露；UI 暴露的是下面 的档位阈值。

负载档位让「最优」可预测、可解释。主机负载指数 L = max( 共享池 oc / bind_max_oc, VM 池内存用量比, PSI 归一化 )，分三档， 进入 / 退出阈值不同（滞回）+ 稳定期：

档位判定自动 VM 的目标形态
宽裕所有自动 VM 都能独占放下：Σ⌈vcpus/threads_per_core⌉ ≤ 空闲独占核，且每节点内存放得下全部 A：按节点装箱（vCPU 降序 first-fit，内存随 vCPU 同节点），两节点均衡
适中能全部绑节点、不能全部独占A/B 混合：优先级高、CPU 利用率高的保留 / 升为 A；其余 B（cpu.weight 按优先级）；节点间按内存 + vCPU 均衡
紧张内存或 vCPU 超分（oc ≥ release_oc 或内存用量 ≥ 预算）B/C：独占核全部释放回共享池；vCPU 超分在两节点均衡；某节点内存放不下的 VM 允许 C（浮动、跨节点）；内存分层 VM 优先降级（它们对远端访存最不敏感）

档位只决定「目标形态」，具体哪台 VM 落哪个节点、谁保留独占，仍由目标函数决定。

3.10.3 求解与执行（每拍）

触发：VM 启停 / 迁入迁出 / plan 应用完成 / 每 30s 一拍。

① 采样   拓扑 + plan；每 VM：vCPU 利用率（scope cpu.stat）、常驻内存与节点分布
         （numa_maps）、优先级；每节点：oc、空闲独占核、空闲内存、PSI
② 定档   计算 L，按滞回决定档位（进入更高档立即，退出需稳定 promote_stable_s）
③ 求解   以当前放置为初解，目标形态为模板：贪心装箱（固定 VM 先占位 → 自动 VM 按
         优先级、vCPU 降序 first-fit 到 Cost 增量最小的节点/等级）→ 局部搜索（两两交换、
         单台迁移）直到 Cost 不再下降。VM 数在百量级，毫秒级完成
④ 差分   目标 vs 当前 → 动作列表，按成本排序：解绑核（免费）→ 绑核（免费）→
         改 cpu.weight（免费）→ 收编 C→B（几乎免费，只写 cpuset）→ 换节点（有成本）
⑤ 执行   免费动作本拍全部执行；换节点每拍最多 1 台、主机同一时刻最多 1 个内存迁移；
         每台 VM 冷却 cooldown_s；VM 启动后 settle_after_boot_s 内不动
⑥ 记录   placement_event（动作、from/to、触发指标快照、收益估计）+ WS 推送

启动时准入是同一求解器的增量调用：新 VM 按当前档位的目标形态入场（宽裕 → A， 适中 → 按优先级 A 或 B，紧张 → B 或 C），不为它挤动别人；下一拍再做全局优化。 准入在虚拟机监控服务 launch_vm 前由宿主机代理决定（同一台主机上串行，避免两台 VM 同时抢同一批核），结果随启动参数一起下发；启动后 placement_tier 落库并推 WS。

oc 的口径：节点共享池超分比 = Σ落在该节点的 B/C 级 vCPU ÷ 扣除独占后的共享线程 数；B 级 vCPU 全算到其绑定节点，C 级（浮动）VM 的 vCPU 按各节点共享线程数占比 分摊到每个节点，避免浮动 VM 在 oc 里被漏算或重复算。节点 CPU 压力：cpu.pressure 不分 NUMA 节点，取该节点上所有 VM scope 的 cpu.pressure some avg60 按 vCPU 数加权 聚合，或用 per-cpu /proc/stat 折算该节点共享线程的 busy%。

守卫：plan 应用中、主机参与在线迁移中、内存分层处于下刷档时全部暂停； mode=advise 只记录建议不执行（页面显示「建议」，供上线初期观察）； dedicate_max_oc < release_oc 且 promote_stable_s > 0 是硬校验，保证 A/B 不会 反复升降。所有决策写 placement_event（§4.1）可审计。

一个例子（2 节点 × 8 核 16 线程，共享池每节点 6 核）：早上只有 3 台自动 VM （4/4/8 vCPU）→ 宽裕档，全部 A，N0 放 4+4、N1 放 8。中午再启 6 台 → 求解发现独占核 不够 → 适中档：优先级 high 的 8 vCPU 保留 A，其余转 B，两节点各 4 到 5 台；转换只是 解绑 + 改 cpuset，秒级完成。傍晚内存用量顶到预算 → 紧张档：剩余 A 释放，两台内存分层 VM 转 C 允许跨节点；一台 12G 的 B 级 VM 因 N0 内存吃紧被搬到 N1（先切 vCPU，内存 后台迁页约 10s）。晚上 VM 陆续关机 → 稳定 5 分钟后逐拍升回 A，每拍最多一次换节点。

3.10.4 在线调整的方法（确定项）

前置：VM 已在独立 scope（§3.3）。不需要 QEMU 配合，也不需要 guest 配合。

调整项方法生效说明
vCPU 可用范围 / 整 VM 换节点systemd SetUnitProperties(scope, runtime=true, AllowedCPUs=…) = 写 cpuset.cpus即时（内核在下一个调度点迁移线程，µs–ms 级）一次覆盖 vCPU + 模拟器 + iothread 全部线程

KVM 侧发生什么：页迁移经 mmu_notifier 使 EPT 项失效，vCPU 下次访问该页 触发 EPT violation 重建映射——guest 只感到该页一次短暂停顿，看不到任何拓扑变化 （非 vNUMA 的 guest 拓扑本来就是单节点）。vCPU 线程换核对 guest 完全透明。

为什么不选其它路：QEMU 没有运行时改 host-nodes 的 QMP（memory-backend 属性 启动后只读）；guest 内 balloon/热插拔改的是容量不是位置；内核自动 NUMA 平衡 （kernel.numa_balancing）是全局开关、按页扫描制造 EPT 抖动且与本控制器互相 搬动——主机上关掉它（=0），由控制器做粗粒度、可审计的迁移。

1 准入   非 vfio / 非 1G 大页 / 非 vNUMA；目标节点 free_mem ≥ resident×1.1（A 级再要
         ⌈vcpus / threads_per_core⌉ 空闲核）；主机无其它进行中的迁移；内存分层 VM → 通知总控对该 VM

3.10.6 限制与上线验证项（6.7）

  • vfio 直通：全部 guest 内存被 pin，migrate_pages 返回 EBUSY——强制 manual。
  • 1G 大页：hugetlb 迁移要求目标节点有空闲 1G 页、且逐页拷贝慢——排除在自动之外； 2M 大页允许，准入时校验目标节点 free_hugepages。
  • 内存分层 VM：uffd-wp 页（PTE marker，5.19+）在页迁移下的行为要在我方分支 （swap-cache 设计）上实测——验证项 #1；已换出页不在内存，不受影响。
  • 分布式存储 vhost 后端共享 memfd：后端进程映射同一内存，MOVE_ALL 覆盖共享页；IO 进行中 的页被临时 pin 时内核重试——验证项 #2：迁移期间持续 fio 无错误。
  • 迁移吞吐与 EPT 抖动：验证项 #3：8G/32G VM 迁移耗时、guest 内延迟毛刺分布，据此 定 max_move_gb（默认 64）与是否需要分片（move_pages 路径）。
  • cpuset 与 affinity 交互：验证项 #4：在 6.7 上确认缩 cpuset 后再扩回，vCPU 的 1:1 pin 自动恢复（user_cpus_ptr 语义），否则控制器在扩池后重下发 pin。
  • 迁页与内存策略/共享映射：验证项 #5：绑定单节点 VM 改 cpuset.mems 后，若 QEMU 仍带 host-nodes（vNUMA memdev）MPOL_BIND 的 nodes_remap 是否跟上；memfd 共享映射在 分布式存储后端侧（另一个进程、另一个 cgroup）的迁页表现——页归谁计费、是否被后端 的 mbind 顶回。

4.4 校验规则（validate 与 apply 共用）

  • 池两两不交、并集 = 全部在线 CPU；HT 兄弟同池；system ≥ 2C、virt ≥ 2C。
  • 缩池冲突：目标池变更后，受影响核上有运行中 VM 的独占绑定 → 列出阻塞 VM 清单拒绝 （需先解绑/迁移/关机）。
  • spdk 池变更时校验 isolated 前提：扫根下全部子 cgroup（含临时 scope / 容器运行时的组） 的 cpuset.cpus 与 spdk 池无重叠；apply 后回读 cpuset.cpus.partition，非 isolated 即失败并原样上报原因字符串。
  • 大页：目标值 < 当前 nr - free（在用）→ 拒绝；1G 增量运行时分配失败 → 降级为 pending-reboot 而非失败。
  • 内存预算不等式（§3.4）成立且安全余量 ≥ 4%（残差按观测峰值）；machine.slice 的 memory.max 由校验器推导、不可手填；VM 池预算低于运行中 VM 保证线 → 拒绝， 低于超分线 → 警告；模式 C VM 只以 overhead 计入 VM 池、主内存计入大页池。
  • VM 放置：pins ⊆ 所属池；模式互斥矩阵（§2.3）；模式 C 的节点大页余量足额。
  • 浮动 VM 与共享池：共享池可用线程（扣独占）为 0 而有运行中浮动 VM → 拒绝； 可用线程 < 任一浮动 VM 的 vCPU 数 → 拒绝；Σ浮动 vCPU / 可用线程 > 4 → 警告； 某节点共享池核为 0 → 警告（该节点上的浮动内存将跨节点访问）； 绑定单节点的共享 VM 所在节点共享池核为 0 → 拒绝。
  • 自动放置（§3.10）：控制器只动 placement_source=auto 的 VM；vfio / 1G 大页 / vNUMA VM 强制 manual；换节点前目标节点 free_mem ≥ resident×1.1（2M 大页 VM 另查目标节点 free_hugepages）；主机同一时刻最多一个内存迁移。plan 编辑缩池时，控制器先暂停， 应用完成后下一拍按新池重新平衡（不由 validate 拒绝）。

§8 风险与已知坑

  • 存量 QEMU 迁入 scope 的计费偏差：已 fault 的匿名页留在旧 cgroup 计费， memory.current 初期偏低（§3.3）。选择「重启渐进生效」或接受初期统计偏差并在 UI 标注。
  • 缩 cpuset 与线程亲和的顺序：先清/改线程 sched_setaffinity 再缩 scope cpuset；6.7 内核（v6.2+ user_cpus_ptr）在 cpuset 变更时会自动取交集、交集为空 回退 cpuset 全集，但 sched_setaffinity 调用本身遇到与当前 cpuset 交集为空的 mask 仍返回 EINVAL——换节点必须「解 pin → 改 cpuset → 重 pin」（§3.10.5）；扩回池后 pin 是否自动恢复要实测（§3.10.6 验证项 #4）。
  • 新 VM 必须在 exec 前进入 scope：先起 QEMU 再搬 pid 会让 prealloc 的内存与 大页永久计费到虚拟机监控服务的 cgroup（§3.3）——hugetlb.*.max 对这台 VM 形同虚设。 代码评审把这条当硬性检查项。
  • isolated 分区写入失败的表现：6.7 上约束不满足时写入不返回 EINVAL，写成功 但状态变为 isolated invalid (<原因>)，原因字符串直接可读（如 `Cpu list in cpuset.cpus not exclusive`）——agent 回读解析上报即可，不必逐 slice 猜冲突。冲突 只看兄弟 cgroup 已配置的 cpuset.cpus，对账时扫根下全部子 cgroup（§3.2）。
  • 1G 大页运行时分配：开机越久成功率越低；已按「pending-reboot 降级 + 开机早期 投放」设计，不要在 apply 里无限重试 compact。
  • memory.min 过配：Σ min 逼近 MemTotal 会把全局回收逼到无页可扫、触发 OOM—— 预算不等式的 4% 安全余量是硬校验，不给 UI 绕过入口。
  • VM 池 memory.high 节流的连带效应：顶到 high 后 QEMU 线程会被 reclaim 节流， vCPU 出现毛刺——内存分层水位线应设在 high 之前触发（预算项进压力合成正是为此， §3.7）。
  • vhost-net/内核线程不可归户：其 CPU 落「内核/其它」段；重 IO 的 VM 会让该段 偏大，口径说明要写进 tooltip，避免被当成泄漏排查。
  • systemd 与手写 cgroupfs 的共管边界：AllowedCPUs 走 systemd（防 daemon-reload 覆盖）；partition/hugetlb 上限走直写 + 开机单元重放；不要两边写同一属性。
  • 单 NUMA 开发机 vs 多 NUMA 生产机：所有 per-node 逻辑必须在 node 数=1 时退化 正确；autotest 用例要在两种拓扑各跑一轮。
  • 分布式存储 OSD 的突发 CPU：recovery/rebalance 时 virt 池可能被打满，影响管理面 响应——virt 池规模建议随「是否跑 OSD」联动，页面在 virt 池 PSI 高时给提示。
  • 自动放置抖动（§3.10）：阈值太近会让 VM 在 A/B 间反复升降、或两节点来回搬—— 升降各自独立阈值（1.0 / 1.5）+ 稳定期 + 每 VM 冷却 + 每拍一件事是硬性守卫；上线 先 advise 模式看一周决策日志再切 apply。
  • cpuset.mems 迁页是异步且不可取消的：写下去内核 workqueue 就开始搬，中途改主意 只能再写回原节点（等于再搬一次）——控制器对「进行中」的 VM 不再下发任何新决策， 超时也只标「部分迁移」不回滚。
  • 迁页期间的 guest 毛刺：每页一次 EPT 重建 + 迁页占用内存带宽；对延迟敏感 VM 应设 placement_source=manual 锁死；max_move_gb 限制单次搬动规模。
  • 内核自动 NUMA 平衡与控制器打架：主机 kernel.numa_balancing=0（主机初始化 sysctl drop-in），否则内核会按页扫描把控制器刚搬好的页再挪走并制造 EPT 抖动。
  • vfio / 1G 大页 / vNUMA VM 不可自动搬：pin 页不能迁、1G 需目标有空闲页且慢、 vNUMA 缺 per-memdev 迁移原语（待 x-memdev-rebind）——统一强制 manual，UI 标明原因。
