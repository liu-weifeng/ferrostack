QEMU · Memory Tiering · x-memtier-query

MemTierInfo 字段手册

x-memtier-query 对每个分层区域返回一个 MemTierInfo。 这份手册逐字段说明它是什么、由哪条路径更新、怎么解读、和哪些字段一起看。 先讲三类字段的读法，再逐个展开，最后给出派生指标、一致性检查、样例解读和异常速查。 离线可读，可直接打印。

先分清三类字段

返回的 21 个字段按更新方式分三类，读法完全不同：

状态当前快照，直接读 累计从 enable 起单调递增，只看差分 瞬时最近一个窗口的值，直接读但有滞后
  • 状态字段回答"现在是什么样"，比如常驻多少字节。两次查询之间可以任意变化。
  • 累计字段回答"从开启到现在总共发生过多少次"。单个值没有意义，必须用两次查询的差除以时间间隔换算成速率。重新 enable 后从 0 开始。
  • 瞬时字段由 worker 线程按自己的节拍采样，最长滞后一个节拍（约 200 ms），排水期更新更频繁。

所有计数由 QEMU 内部用原子操作维护，查询本身不加锁、不暂停任何线程，可以按秒级频率安全轮询。多个状态字段之间不保证同一瞬间一致，差异在一个节拍以内。

标识与配置

idstr状态
含义
被分层的 RAM block 名称，例如 x86 机型上主内存是 pc.ram，用 memdev 时是 memdev 的 id。
怎么用
作为其他命令的 id 参数。只有一个区域时可以省略，引擎默认取最大的客户机 RAM block。
注意
一台 VM 可能有多个 RAM block（vNUMA 每个节点一个 memdev）。x-memtier-query 不带 id 时返回全部区域，每个区域一条记录，监控要逐条处理再汇总。
enabledbool状态
含义
该区域的分层当前是否处于活动状态。
怎么用
为 false 时其余字段是最后一次 disable 前的残留或零值，不要拿来算速率。监控在 false 时应把该 VM 标为"未分层"而不是画一条零线。
注意
x-memtier-disable 执行期间（同步读回全部换出页，可能持续几十秒）它仍为 true，此时 swapped-bytes 会快速下降到 0，可据此判断 disable 进度。
pathstr，可选状态
含义
后备设备路径。裸设备如 /dev/nvme1n1p3，预分配文件如 /nvme/tier/vm-a.raw，SPDK 模式是 spdk:0000:5e:00.0。
怎么用
监控用它找到对应的块设备去读 iostat；共享后备迁移前用它核对两端是否指向同一卷。
注意
未启用时缺省（字段不出现）。多台 VM 的 path 不允许相同：后备是易失 swap 语义、盘上无元数据，两台 VM 共用一个设备会互相覆盖。
policyenum状态
含义
当前生效的预设：conservative / balanced / aggressive / custom。
怎么用
只是一个标签。真正决定行为的是下面的 tunables，因为覆盖值会压在预设之上。看到 balanced 不等于所有旋钮都是 balanced 的默认值。
tunablesMemTierTunables状态
含义
解析并钳制之后的生效值，不是用户输入的原始值。每个字段都会出现，即使用户从未设置过。
怎么用

这是唯一能确认"引擎现在到底按什么参数在跑"的地方。几个典型的差异：

  • 用预设时 min-resident-mb 显示的是按区域大小算出来的具体 MB 数，不是百分比。
  • 没设过 target-resident-mb 时它等于 min-resident-mb，表示主动换回关闭。
  • 设了 swapin-watermark ≥ psi-trigger 时这里显示的是被钳到 0.9 倍后的值。
  • 设了 idle-streak: 0 时这里显示 1。
注意
监控面板上"当前下限 / 上限 / 是否武装"三个显示项就从这里取 min-resident-mb、target-resident-mb、psi-trigger。

容量与水位

六个字节数分两组：三个描述客户机内存在哪里，三个描述后备设备的空间。

resident 56%
swapped 37%
未触碰

一个区域的 total-bytes 由三部分构成。第三部分没有字段，是算出来的。

total-bytesuint64状态
含义
区域大小，即这个 RAM block 的字节数。启用后不变。
怎么用
所有比例的分母。也是页元数据规模的依据：每 4K 页 8 字节元数据，32 GB 区域对应 64 MB。
resident-bytesuint64状态
含义
当前在宿主机 DRAM 里、且已经被客户机触碰过的页的字节数。状态机里 RESIDENT、EVICTING、EVICTING_DIRTIED 三态的页都算。
更新
换出完成时减 4K（worker），换入完成时加 4K（fault 线程或主动换回）。enable 时按 pagemap 统计真实在内存的页数作为初值，而不是假设全部常驻。
怎么用

这是最重要的水位。对照 tunables.min-resident-mb：

  • 强制排水（psi-trigger=0）下它应该在几秒到几十秒内落到下限。
  • 停在下限之上排不下去：冷页不够，工作集比下限大；或者 page_idle 失效在等 write-aging 回退（连续 30 个窗口后自动切换）。
  • 在下限附近反复小幅上下：换出与换入乒乓，需要加 hysteresis-mb。
注意
它不是宿主机对这台 VM 的 RSS。QEMU 自身的堆、设备模拟缓冲、其他未分层的 RAM block 都不在里面。要看进程真实占用仍需读 cgroup 的 memory.current。
swapped-bytesuint64状态
含义
当前内容只存在于后备设备上、宿主机物理页已释放的页的字节数。状态机里 SWAPPED 和 FAULTING_IN 两态。
更新
换出完成时加 4K，换入完成（被动或主动）时减 4K。
怎么用

这部分内存不占宿主机 DRAM。它是"借出去"的量，主机内存构成图上应作为独立段画出来，让 DRAM 恒等式闭合：

DRAM = 内核 + 预留 + Σ resident + 空闲      （Σ swapped 不在等式里）

换出比例 = swapped / total，是"这台 VM 超分到多深"的直接度量。

注意
resident + swapped ≤ total，差值是客户机从未触碰过的页，既不占 DRAM 也不占盘。刚启动的 VM 差值很大，运行越久越小。
backing-total-bytesuint64状态
含义
后备设备容量，enable 时从设备或文件大小取得。
怎么用
容量规划的校验：至少要能装下 total − min-resident，否则排水到下限之前就会满。上限 2 TB（29 位 slot × 4K）。
backing-used-bytesuint64状态
含义
后备设备上已分配的 slot 字节数。
更新
换出提交前分配（加），换入完成、换出回滚、写失败时归还（减）。
怎么用

后备使用率 = used / backing-total。接近 100% 会触发 MEMTIER_BACKING_FULL 事件，换出暂停。

它通常略大于 swapped-bytes：差值是正在换出中（EVICTING，已分配 slot 但还没完成）的页。稳态下两者相等。

注意
这是逻辑分配量，不是设备的物理写入量。设备 iostat 的累计写字节会远大于它，因为同一个 slot 会被反复分配、写入、释放。
backing-largest-free-bytesuint64状态
含义
后备设备上最大的一段连续空闲空间。
怎么用

碎片度指标。换出是按连续段（最多 128 页 = 512 KB）申请空间的，申请不到整段时会拆成小写。定义：

碎片度 = 1 − largest-free / (backing-total − backing-used)

接近 0 表示空闲空间基本连成一片；接近 1 表示被切碎。碎片度高时 evict-mbps 会掉，因为顺序大写退化成随机小写。

注意
碎片来自散点换入：换出是连续段，换入是随机单页，释放的 slot 在空闲空间里形成空洞。分配器释放时会合并相邻空洞，碎片随时间自然收敛，不需要人工整理。largest-free < 512 KB 但总空闲还很多，是碎片化严重的信号。

累计计数

五个页计数，从 enable 起单调递增。用法只有一种：两次查询做差，除以间隔秒数。

evicted-pagesuint64，页累计
含义
成功换出的页数：写盘完成、确认未被写脏、物理页已释放。
更新
worker 线程，换出完成裁决为"干净"时加 1。
怎么用

换出速率（页/秒）= Δevicted / Δt。乘 4096 是字节速率，与 evict-mbps 应基本一致（后者是引擎内的 1 秒滚动窗口，前者是你的采样窗口）。

也是误逐率的分母。

注意
同一页被换出、换入、再换出会计数两次。所以它可以远大于 total 的页数，这是正常的。
evict-abortsuint64，页累计
含义
换出被回滚的页数：加了写保护、写盘期间客户机写了这页（WP 故障），完成时发现已脏，回滚为 RESIDENT。也包括写盘失败的回滚。
更新
worker 线程，换出完成裁决为"脏"或"失败"时加 1。
怎么用

这是选页质量最直接的指标。扫描器认为冷的页，在换出的几毫秒窗口内就被写了，说明它其实是写热页。

误逐率 = Δevict-aborts / (Δevicted-pages + Δevict-aborts)

（分母用"尝试换出的总页数"更准确；文档里简写为 aborts/evicted，量级相同。）

解读
误逐率含义处置
< 1%选页质量好无
1% ~ 5%工作集边界附近有抖动加 hysteresis-mb，或延长 cooldown-ms
> 5%在啃写热页调大 cold-runs / idle-streak，或换 conservative
> 20%热度识别基本失效检查是否掉进 write-aging 回退、客户机内存是否被 THP 背书
注意
write-aging 回退模式下这个值天然偏高，因为回退模式就是靠"换出被写脏"来过滤写热页的。回退模式下 10% 以内都算正常。
swapin-faultsuint64，页累计
含义
被动换入次数：客户机访问已换出页，触发 MISSING 缺页，fault 线程从后备读回。
更新
fault 线程，每完成一次读回并 UFFDIO_COPY 填入加 1。多个 vCPU 同时踩到同一页只计 1 次（并发缺页者共享一次读）。
怎么用

缺页速率（次/秒）= Δswapin-faults / Δt。这是客户机正在付出多少延迟代价的直接度量：每次缺页 vCPU 硬停驻 20 到 100 µs。

  • 热集负载稳态下应趋近 0。
  • 刚排水完的几分钟内偏高是正常的收敛过程，随后应下降。
  • 持续高（例如 > 10000 次/秒）说明换出过度：读热页被误换出。写热页会被 evict-aborts 挡住，但 write-aging 回退模式看不到读热度，只能靠这个指标发现。
注意
从未触碰过的页首次访问走 UFFDIO_ZEROPAGE 直接给零页，不计入这个计数，也不产生盘读。
swapin-errorsuint64累计致命
含义
从后备设备读回失败的次数。
怎么用

正常值永远是 0。页内容此刻只存在于后备设备上，读不回就是数据丢失，引擎会发 MEMTIER_SWAPIN_ERROR 事件并让 QEMU 退出。所以实际上你很难查到非零值：查到的时候 VM 已经没了。

监控应订阅事件而不是轮询这个字段。

注意
主动换回的读失败不计入这里，也不致命：它恢复 SWAPPED 状态让被动路径重试。
active-swapinsuint64，页累计
含义
主动换回的页数：不是客户机访问触发的，是控制器在宿主机空闲时按"最近换出优先"预取回来的。
更新
worker 线程每个节拍执行主动换回，每成功一页加 1。
怎么用

主动换回速率 = Δactive-swapins × 4096 / Δt，应不超过 tunables.max-swapin-mbps。

target-resident-mb == min-resident-mb 时主动换回关闭，这个值不会增长。

被动 + 主动的总换入 = Δswapin-faults + Δactive-swapins，才是后备设备承受的全部读压力。

注意
主动换回的页如果恰好有客户机缺页停驻在上面，那一次 UFFDIO_COPY 同时满足两者，只计入 active-swapins。

瞬时值

evict-mbpsuint32，MB/s瞬时
含义
最近 1 秒滚动窗口内的换出吞吐。
更新
worker 线程按窗口统计，同一个值也用于 max-evict-mbps 限速判断。
怎么用
  • 排水期应贴近 tunables.max-evict-mbps。明显低于上限：后备设备写带宽不够、或碎片化导致大写拆小、或冷页供给不足（扫描找不到那么多冷页）。
  • 稳态应接近 0。长期不为 0 说明宿主机持续有压力在持续排水，或者和换入形成了乒乓（对照缺页速率）。
注意
它是 uint32 的 MB/s，精度只到 1 MB/s，低速时显示 0。要看细粒度用 Δevicted-pages 差分。
psi-some-avg10number，%瞬时
含义
worker 最近一次采样到的宿主机 /proc/pressure/memory 的 some avg10：过去 10 秒内有任务在等内存的时间占比。
怎么用

对照两道门：

  • psi ≥ tunables.psi-trigger 才允许换出。
  • psi < tunables.swapin-watermark 才允许主动换回。

用它解释"为什么没在换出"：resident 高于下限但 evict-mbps 为 0，先看 psi 是否低于 trigger。

注意
这是宿主机全局值，所有 VM 查到的都一样（采样时刻略有差异）。有主机级控制器时它把 psi-trigger 设成 0 或 100，这个字段就只剩参考意义。

缺页延迟分段

较新版本增加的三个字段，把一次被动换入在 QEMU 内可见的部分拆成三段，都是累计平均值（纳秒）。它们回答"缺页慢在哪一段"。

客户机访问已换出页
  │  ← 约 5 µs：VM-exit、uffd 入队、vCPU 睡眠（QEMU 看不见）
  ▼
fault 线程拾取故障 ──── swapin-avg-wait-ns ────► 提交读
  ▼
后备设备读 4K ───────── swapin-avg-device-ns ──► 读完成
  ▼
UFFDIO_COPY 填入 ────── swapin-avg-publish-ns ─► vCPU 被唤醒
  │  ← 约 2 µs：VM-entry、EPT 二次缺页（QEMU 看不见）
  ▼
客户机继续执行
swapin-avg-wait-nsuint64，ns累计平均
含义
fault 线程从 uffd 读到故障消息，到把读请求提交给后备设备之间的平均耗时。
怎么用

反映 fault 线程本身的响应能力。

量级状态
0.2 µsfault 线程独占核忙轮询（SPDK 模式），已到极限
5 ~ 20 µsio_uring 模式、不绑核：含一次调度唤醒
> 50 µsfault 线程在和别的负载抢 CPU，或缺页并发超过 bounce 池（64）在等回收
swapin-avg-device-nsuint64，ns累计平均
含义
从提交读到读完成的平均耗时，即后备设备的 4K 读延迟（含队列等待）。
怎么用

它应接近介质的裸延迟：Optane 10 ~ 12 µs，企业级 NVMe 50 ~ 80 µs，消费级 NVMe 80 ~ 100 µs。

明显高于裸延迟，几乎总是读在等写：NVMe 没有抢占，换出的 512 KB 大写在飞时，后面的读要等它完成。写带宽慢的盘上这条尾巴可以到毫秒级，实测读尾延迟 ≈ 在飞写字节 ÷ 写带宽。处置是调小 max-evict-mbps。

排除了换出干扰仍然高：盘在退化，或同一块盘上有别的负载。后备设备应独占。

注意
这是平均值，尾延迟看不到。要看尾延迟用设备侧 iostat 的 r_await 或客户机内探针。
swapin-avg-publish-nsuint64，ns累计平均
含义
从读完成到 UFFDIO_COPY 返回（页已填入、vCPU 已唤醒）的平均耗时。
怎么用

正常 3 ~ 4 µs。其中 memcpy 4K 只占 0.3 µs，大头是内核分配页、建页表、唤醒等待者。这一段基本是固定成本，不受配置影响。

明显变大：宿主机内存分配变慢（碎片化、正在直接回收），或 THP 相关的页表操作。这时通常宿主机整体已经有压力，对照 psi-some-avg10。

三段之和加上 QEMU 看不见的约 7 µs（VM-exit/entry 各一次、uffd 入队、vCPU 睡眠唤醒、EPT 二次缺页）就是客户机感受到的一次缺页延迟。最好的配置（Optane、SPDK、绑核）下总计约 21 µs，其中器件占一半。

派生指标

面板上真正要画的大多是派生量。全部从两次查询（间隔 Δt 秒）算出：

指标公式单位用途
常驻比例resident / total%对照下限，看排水是否到位
换出比例swapped / total%超分深度
未触碰比例1 − (resident + swapped) / total%刚启动的 VM 很大，可用来判断 VM 是否"热身完毕"
换出速率Δevicted-pages × 4096 / ΔtB/s与 evict-mbps 互相印证
被动换入速率Δswapin-faults / Δt次/s客户机付出的缺页代价
主动换回速率Δactive-swapins × 4096 / ΔtB/s回血进度
后备读压力(Δswapin-faults + Δactive-swapins) / ΔtIOPS对照设备 IOPS 上限
误逐率Δevict-aborts / (Δevicted-pages + Δevict-aborts)%选页质量
后备使用率backing-used / backing-total%满盘预警
后备碎片度1 − largest-free / (backing-total − backing-used)0..1解释 evict-mbps 掉速
在途换出量backing-used − swappedB正在写盘、尚未裁决的页；稳态应为 0
缺页均延迟（QEMU 内）wait + device + publishns加约 7 µs 得客户机感受值
主动换回是否开启tunables.target > tunables.minbool面板状态位
换出门是否开着psi-some-avg10 ≥ tunables.psi-triggerbool解释"为什么不换"

采样间隔建议 5 秒。累计计数是 64 位，不会回绕；重新 enable 会归零，采集器检测到值变小就重置基线。

一致性检查

这些关系在任何一次查询里都应成立（允许一个节拍内的微小偏差）。采集器可以用它们做自检，不成立说明查询结果来自 disable 过程中或引擎异常：

关系说明
resident + swapped ≤ total差值是未触碰页
swapped ≤ backing-used ≤ backing-total差值是在途换出
largest-free ≤ backing-total − backing-used最大连续空闲不超过总空闲
tunables.min ≤ tunables.target ≤ total/MB工作带不变式，引擎钳制保证
tunables.swapin-watermark < tunables.psi-trigger换出与换回的 PSI 区间不相交，引擎钳制保证
Δevicted ≈ Δswapped/4096 + Δfaults + Δactive换出的页要么还在盘上，要么已被换回（在一个采样窗口内近似成立）
swapin-errors == 0非零意味着 VM 正在退出

一个完整样例

8 GB 客户机，后备 16 GB 消费级 NVMe 分区，balanced 预设并覆盖了下限。两次查询间隔 5 秒。

第 1 次                                第 2 次（5 秒后）
"total-bytes":          8589934592      8589934592
"resident-bytes":       4831838208      4563402752
"swapped-bytes":        3221225472      3489660928
"backing-total-bytes": 17179869184     17179869184
"backing-used-bytes":   3221225472      3490709504
"backing-largest-free-bytes": 13958643712  13689159680
"evicted-pages":           1843200         1911296
"evict-aborts":              12034           12410
"swapin-faults":           1056768         1058304
"swapin-errors":                 0               0
"active-swapins":                0               0
"evict-mbps":                    0              52
"psi-some-avg10":              0.4            12.3
"swapin-avg-wait-ns":         8200            8400
"swapin-avg-device-ns":      91000           97000
"swapin-avg-publish-ns":      3600            3600
"tunables": { "min-resident-mb": 4096, "target-resident-mb": 4096,
              "psi-trigger": 10, "swapin-watermark": 5, ... }

逐项解读：

  1. 宿主机压力刚起来。psi 从 0.4 涨到 12.3，超过了 trigger 10，换出门打开。第 1 次查询时 evict-mbps 为 0 是因为门还没开，不是坏了。
  2. 正在排水。resident 从 4.5 GB 降到 4.25 GB，5 秒减了 256 MB，约 51 MB/s，与 evict-mbps 52 吻合。Δevicted = 68096 页 × 4K = 266 MB，也吻合。
  3. 离下限还有 156 MB。4.25 GB − 4096 MB。按这个速度 3 秒后到底。之所以只有 52 MB/s 而不是上限 500，是 PSI 刚过线、扫描批次还小，下一次查询应看到更高。
  4. 选页质量正常。Δaborts = 376，Δevicted = 68096，误逐率 0.55%。
  5. 客户机基本没在付代价。Δfaults = 1536，即 307 次/秒缺页，很低。排水刚开始，被换出的确实是冷页。
  6. 后备健康。使用率 20%；在途换出 = used − swapped = 1 MB，正常；碎片度 = 1 − 13.69/13.69 ≈ 0。
  7. 器件延迟略升。device 从 91 µs 到 97 µs，是换出写开始挤占读。消费级 NVMe 的裸延迟就在 90 µs 上下，这个幅度可以接受；如果涨到 300 µs 以上就该压 max-evict-mbps。
  8. 主动换回关闭。target == min，active-swapins 为 0 是预期的。
