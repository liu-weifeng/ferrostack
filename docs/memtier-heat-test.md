# 内存分层热度分布接口(x-memtier-query-heat)测试报告

> 测试节点 **10.8.1.195**,2026-11-10。被测:qemu `memtier-heat` 分支(最终提交 `d9cff878a1`,
> 已合入 `stable-11.1-dev`,合并提交 `f10e49dac5`)。对照:不含本次改动的 `0c8509f490`。
>
> 结论先行:接口可用、结果可信到"定量级";对客户机没有可见影响;全量扫描的主机 CPU 开销偏高,
> 生产上建议用抽样。合入后有一项需要知道的行为变化:写密集负载下换出器现在能守住下限,
> 换入随之增多(见 §4)。

---

## 1. 被测内容

| 项 | 说明 |
|---|---|
| `heat-scan-period-ms` | 热度扫描周期,0(默认)为关闭,低于 1000 抬到 1000 |
| `heat-sample-percent` | 抽样比例 1–100(默认 100),只扫一部分 2MB 单元再按比例放大 |
| `x-memtier-query-heat` | 返回 9 个空闲时长桶(下界 0、周期×1、×2 … ×128),每桶给出常驻字节、已换出字节、累计再访问页数 |
| 扫描读位图方式 | 只读用到的 page_idle 位图字,不再按物理页号跨度整段读(换出扫描同样受益) |
| 写老化回退 | 回退前先探测 idle 位能否保持;热度扫描看到空闲页时也不回退 |

用法:从最冷的桶往回累加到空闲时长 T,常驻 + 已换出字节之和是可换出量,再访问页数两次查询的差值
除以间隔是预计每秒换入页数。

## 3. 准确性

### 3.1 直方图对比真值

热度扫描 2 秒周期,不换出,运行约 11 分钟后取最后 5 分钟。已知负载的期望值:周期 P 的区域,
页的空闲时长在 0–P 之间均匀分布,每页每 P 秒被再访问一次。

再访问速率(页/秒):

| 负载 | 所在桶 | 真值 | 全量扫描 | 偏差 | 10% 抽样 | 偏差 |
|---|---|---|---|---|---|---|
| 1GB / 12 秒 | ≥8 秒 | 21845 | 20162 | −7.7% | 21683 | −0.7% |
| 1GB / 60 秒 | ≥32 秒 | 4369 | 4090 | −6.4% | 4430 | +1.4% |
| 1GB / 300 秒 | ≥256 秒 | 874 | 823 | −5.8% | 885 | +1.3% |

- 全量扫描在中间版本上同配置测到过 −1.7% ~ −2.0%,轮次之间有几个百分点的波动。
- 各桶常驻字节与期望的偏差:全量 ±45MB 以内,10% 抽样 ±80MB 以内(最冷桶除外,它还包含客户机
  自身约 1.65GB 的闲置内存,无法给出真值)。
- 真值为 0 的桶里有少量噪声计数,全量最大 446 页/秒(≥2 秒桶),≥16 秒的桶都在 80 页/秒以下。

### 3.2 按直方图定下限后的实际换入率

在同一台虚拟机上,用直方图算出阈值 T 对应的可换出量和预计换入率,把 `min-resident-mb` 设成
"当前常驻 − 可换出量",`psi-trigger` 设 0,运行 10 分钟,取后 5 分钟的实际 `swapin-faults` 速率。

| 阈值 T | 可换出量 | 下限 | 预计换入 | 实际换入 | 实际 / 预计 |
|---|---|---|---|---|---|
| 空闲 ≥128 秒 | 3902MB | 3374MB | 836 页/秒 | 1754 页/秒 | 2.10 |
| 空闲 ≥32 秒 | 3970MB | 2725MB | 5242 页/秒 | 5996 页/秒 | 1.14 |

- 偏高的原因:换出器按游标轮转、过了 `idle-streak` 就换,不是严格最冷优先。阈值 128 秒那一轮,
  已换出的页里有约 100MB 空闲时长只有 16–64 秒。
- 阈值 32 秒那一轮,常驻量停在下限上方约 300MB:换出器找不到足够冷的页就不再往下压。
- 这条曲线适合用来定量级,不适合当精确值。

## 4. 对现有换入换出的影响

redis 基准,下限 4096MB(50%),每档跑两次(正序、反序各一次),最终提交。

| 版本 | GET 次/秒 | GET p99 | 换入设备耗时 | SET 次/秒 | worker CPU |
|---|---|---|---|---|---|
| 对照版 | 35568 / 35865 | 2.83 / 2.85ms | 48.6 / 49.0µs | 55707 / 56351 | 84% / 85% |
| 新版,热度关闭 | 35624 / 36325 | 2.80 / 2.71ms | 49.5 / 49.5µs | 39154 / 40334 | 33% / 33% |
| 新版,4 秒全量 | 35288 / 35226 | 2.84 / 2.86ms | 49.1 / 48.9µs | 44771 / 46951 | 69% / 71% |
| 新版,2 秒 10% 抽样 | 35599 / 35341 | 3.04 / 2.86ms | 49.4 / 49.0µs | 43594 / 43887 | 47% / 48% |

- GET 吞吐、p99、换入设备耗时各档一致;换入错误为 0;全程没有写老化回退。
- 数据完整性测试(1 秒周期热度扫描 + 大量换出 + 干净页重换出 + 覆写 + 关闭回收)全部校验通过。

### SET 吞吐的差异(行为变化)

新版 SET 吞吐比对照版低约 30%,两轮回归共 4 次都稳定在 39k 左右。SET 阶段的明细:

| 版本 | SET 结束时常驻 | SET 期间换出页 | SET 期间换入 |
|---|---|---|---|
| 对照版 | 4631 / 4661MB | 12.0 万 / 11.2 万 | 15.3 万 / 15.2 万 |
| 新版,热度关闭 | 4118 / 4117MB | 35.1 万 / 35.2 万 | 25.6 万 / 24.2 万 |
| 新版,4 秒全量 | 4429 / 4591MB | 23.8 万 / 17.4 万 | 20.6 万 / 19.5 万 |
| 新版,2 秒 10% 抽样 | 4112 / 4116MB | 32.5 万 / 31.5 万 | 22.2 万 / 21.8 万 |

- 对照版的 worker 线程被位图扫描占满,写入压力下跟不上,常驻量停在下限上方约 550MB,换出少所以
  换入也少。
- 新版扫描开销降下来,能把常驻量压到下限,换出量约为对照版的 3 倍,换入随之增加。
- 第一轮回归里对照版有一次碰巧压到了下限(常驻 4101MB),那次 SET 只有 32.6k,低于新版同样压到
  下限时的 39k。同等执行力度下新版更快。
- 想要原来的效果:调高 `min-resident-mb` 或调低 `max-evict-mbps`。

## 5. 对虚拟机的影响与资源开销

热度扫描开启,`psi-trigger` 设 99(不换出),客户机跑 redis GET,每档 6 次取平均。

| 档位 | GET 次/秒 | p50 | p99 | worker CPU(客户机空闲 / 繁忙) |
|---|---|---|---|---|
| 关闭 | 128010 | 0.212ms | 0.343ms | 0.2% / 0.2% |
| 4 秒全量 | 127788 | 0.211ms | 0.307ms | 43% / 58% |
| 2 秒全量 | 128140 | 0.215ms | 0.312ms | 57% / 70% |
| 1 秒全量 | 129393 | 0.215ms | 0.316ms | 65% / 73% |
| 2 秒 10% 抽样 | 127330 | 0.208ms | 0.303ms | 14.5% |

- **客户机**:吞吐和延迟的差异都在噪声内。
- **CPU**:开销全在 worker 线程的内核态,来自对每页做 rmap 遍历和 EPT 清 young,与客户机内存量成
  正比、与周期成反比。8GB 客户机 2 秒周期约 0.6 核。
- **1 秒周期跑不满**:实际每遍 2.2 秒,`pass-interval-ms` 如实报告。
- **抽样不是线性省**:10% 抽样是 14.5% 而非 6%,读位图时同一个字里其余物理页也要查一遍。
  表中 14.5% 是全新虚拟机直接开 10% 抽样的数值;从全量切到抽样后,旧的 idle 标记会让 CPU 在一段
  时间内偏高(测到约 20%)。
- **内存**:QEMU 常驻内存增加约 20–28MB(每页 1 字节加扫描缓冲)。

## 6. 接口效率

同一条 QMP 连接上连续调用 2000 次(`x-memtier-query` 200 次):

| 命令 | 应答大小 | 平均 | p99 |
|---|---|---|---|
| `query-status`(基准) | 51B | 0.17ms | 0.41ms |
| `x-memtier-query-heat` | 973B | 0.26ms | 0.45ms |
| `x-memtier-query` | 1895B | 2.1ms | 5.9ms |

以 100Hz 连续调用 `x-memtier-query-heat`,客户机 redis GET 吞吐(127594 对 128006 次/秒)和
p99(0.306 对 0.303ms)无变化。

边界用例均符合预期:未启用分层返回空列表;未知区域返回错误;热度关闭时 `valid` 为 false 且桶为空;
周期 300 被抬到 1000,抽样 0 被抬到 1;改周期或抽样比例后计数清零、`passes` 归零;全量时各桶常驻
字节之和与 `x-memtier-query` 的 `resident-bytes` 一致(1840MB);1% 抽样估出 1861MB。

## 7. 测试中发现并修掉的问题

| 问题 | 现象 | 处理 |
|---|---|---|
| 位图读取范围过大 | 每扫一段都把客户机所有空闲页重新遍历一遍;8GB、2 秒周期 worker 占 80% | 只读用到的位图字,降到约 60%,真值为 0 的桶里的噪声也降了一个量级 |
| 全量扫描 CPU 高 | 见 §5 | 新增 `heat-sample-percent` |
| 抽样逐单元调用 | 10% 抽样仍占 25% | 一次调用批量处理所有抽样单元 |
| 节拍漂移 | 每遍间隔 2.3 秒而非配置的 2 秒 | 改为固定节拍 |
| 写老化回退误触发 | 见下 | 回退前探测 idle 位;热度扫描看到空闲页时不回退 |

### 写老化回退误触发

回退的触发条件是"允许换出,但连续 30 个窗口换出不足一个 2MB 单元"。把下限设在冷集合边缘时正好
满足:每秒几百页换回来,换出器补得比每窗口 512 页慢,于是被判成"page_idle 不可用",永久切到写老化,
随后开始换出读热页。这是既有问题,对照版同样复现。

同一场景(已知负载,下限 3529MB,热度扫描关闭):

| 版本 | 是否回退 | 稳态换入 |
|---|---|---|
| 对照版 | 是 | 约 3400 页/秒 |
| 修复后 | 否 | 约 1020 页/秒 |

该负载的理论值是 874 页/秒。修复后,page_idle 可用但确实没有冷页的区域会停在下限上方(测到高出
约 70–100MB),不再靠换出热页硬压到下限。

## 8. 未覆盖

- 只测了 8GB 客户机,更大客户机的 CPU 开销是按比例推算的。
- "page_idle 确实不可用时仍能回退"这一侧没有实测:现在启用分层时会先拆掉大页,测试机上构造不出
  idle 位保持不住的情况,只是按内核行为推断。
- 开着热度扫描做热迁移和快照没测(代码里迁移期间暂停热度扫描)。
- SPDK 后端没测,测试机上的 SPDK 环境已不在。
- 真实业务负载下"预测换入率"的偏差没测,§3.2 用的是合成负载。

## 9. 使用建议

- 需要定比例时再打开,周期 2–4 秒、抽样 10% 左右;8GB 客户机约占 0.15 核,按内存量线性估算。
- 第一遍只是基线;下界为 N 个周期的桶最早在第 N+1 遍才有数,最冷的桶要 129 遍。
- 选定阈值 T 后,`min-resident-mb` 取"总量 − 可换出量",并给预计换入率留 1–2 倍余量。
- 用实际 `swapin-faults` 速率校验;偏差大时调高下限。
