## 0. 一页纸

- **做什么**：把虚拟机 RAM 里长期没人碰的页写到 NVMe 或共享卷上并释放宿主机
  物理页，客户机再访问时按需读回。宿主机因此可以超分内存，客户机完全无感知，
  不需要客户机内任何驱动。
- **在哪做**：全部在 QEMU 用户态，依赖四个内核现成机制：userfaultfd 接管缺页、
  page_idle 位图观测访问、mmu_notifier 让 KVM 同步页表变化、io_uring 或 SPDK 做
  I/O。不改内核，不改 KVM。
- **热度怎么识别**：主路径是批量扫描 page_idle 位图。它经 mmu_notifier 读写 EPT
  的 Accessed 位，所以客户机的读和写都看得见。两级去抖加冷却期过滤偶发访问。
  page_idle 失效时自动退化为写保护写老化。
- **为什么不用别的**：直接读 EPT A/D 位要改 KVM；宿主机页表的 A 位看不见客户机
  经 EPT 的访问；DAMON 是区域级采样，给不出页级冷热而且是宿主机全局资源；写保护
  只看得见写，而且 KVM 下读也会触发。
- **代价**：稳态零开销，常驻页的访问路径没有任何钩子。元数据约 13 字节每页。
  只有在宿主机有内存压力、需要换出时才扫描和搬页。
- **换出**：冷页连续段一次写保护、一次零拷贝顺序写、锁内释放。零页不落盘，
  换入后未改的页再换出不重写。分块循环日志布局让 NVMe 写放大最小。
- **换入**：缺页驱动，多缺页流水线并发，fault 线程忙轮询，单次约 100 µs（消费级
  NVMe）到 20 µs 级（Optane 加 SPDK）。宿主机空闲时可主动把最近换出的页拉回。
- **迁移**：后备是共享卷时，已换出的页不走网络，只传 gfn 到 slot 的映射表；
  precopy 首轮跳过近期被碰过的热页，避免重复传输；停机时间与换出量无关。

## 1. 问题与约束

虚拟化平台的内存超分有三条路：气球驱动（要客户机配合，回收粒度粗，释放慢）、
内核 swap（粒度细但不区分虚拟机，回收在分配路径上同步发生，尾延迟差，宿主机
级策略无法按虚拟机下发）、宿主机侧的用户态分层（本方案）。

本方案的设计约束：

1. 客户机无感知，不装驱动，不改客户机内核。
2. 宿主机不改内核、不改 KVM，用发行版内核即可。
3. 平时零开销。没有内存压力时，虚拟机的内存访问路径与不开分层完全一样。
4. 按虚拟机控制：每台虚拟机独立的常驻下限、换出速率、优先级，宿主机级控制环
   可以在运行时调整。
5. 后备介质既可以是本地 NVMe，也可以是两端都能访问的共享卷，后者让迁移和
   快照可以不搬运已换出的数据。

## 2. 内存页热度识别

### 2.1 热度到底是什么

分层要回答的是"这一页最近一段时间有没有被客户机访问"。客户机访问内存走的是
硬件二级页表（Intel EPT，AMD NPT），不经过 QEMU 进程的页表，也不产生任何
软件事件。所以"客户机碰了没有"这个信息只存在于两个地方：

- EPT 表项的 Accessed（A）位与 Dirty（D）位，硬件在 TLB miss 时置位（需要 CPU
  支持 EPT A/D 位，Haswell 以后都有）。
- 人为制造的陷阱：把页从 EPT 里拿掉或改成只读，让访问产生 EPT violation，
  在处理路径上记一笔。

所有热度识别方法都是这两个信息源的某种包装。区别在于**谁去读、以什么粒度读、
读一次要付多少代价、能不能区分读和写、要不要改内核**。

### 2.2 候选方法一览

| 方法 | 信息源 | 看得见读 | 看得见写 | 粒度 | 对客户机的扰动 | 改内核/KVM | 结论 |
|---|---|---|---|---|---|---|---|
| 直接读 EPT A/D 位 | EPT 表项 | 是 | 是 | 4K | 清位要刷 TLB | **要**，KVM 没有对用户态暴露 | 不用 |
| 宿主机页表 A 位（`clear_refs` + pagemap） | QEMU 进程页表 | **看不见客户机** | 看不见 | 4K | 无 | 不要 | 不能用 |
| page_idle 位图 | struct page 的 idle 标志，经 rmap 与 mmu_notifier 同步到 EPT A 位 | 是 | 是 | 4K | 清位时 EPT aging，可控 | 不要 | **主路径** |
| DAMON（vaddr / paddr） | 同上，内核采样 | 是 | 是 | 自适应区域（远大于页） | 持续后台采样 | 不要，但要宿主机级配置 | 不用 |
| uffd 写保护 | EPT violation | 否 | 是 | 4K | 每次写一次缺页，约 10 µs vCPU 停顿 | 不要 | 回退路径与换出窗口判脏 |
| KVM 脏页日志（PML） | EPT D 位，硬件日志 | 否 | 是 | 4K | 极低 | 不要 | 与迁移的脏页跟踪冲突，暂不用 |
| mprotect + SIGSEGV | 页表权限 | 是 | 是 | 4K | 每次访问一次信号，VMA 碎片化 | 不要 | 不用 |
| 硬件采样（PEBS/IBS） | 采样寄存器 | 是 | 是 | 采样命中处 | 低 | 要 perf 权限，虚拟化下不稳定 | 不用 |
| 客户机内驱动上报 | 客户机 LRU | 是 | 是 | 客户机页 | 无 | 要客户机配合 | 违反约束 1 |

下面逐个说明为什么不选。

### 2.3 为什么不直接读 EPT A/D 位

从信息质量看这是最理想的来源：硬件维护，读写都记录，4K 精度，读位本身不打扰
客户机。但 KVM 没有把它暴露给用户态：

- 没有 ioctl 可以按 gfn 读或清 EPT 的 A 位。KVM 只暴露 D 位，而且是以脏页日志
  的形式（`KVM_GET_DIRTY_LOG` 或 dirty ring），并且是写时才有。
- 要用就得给 KVM 加接口，走 EPT 页表遍历、按 gfn 清 A 位并处理 TLB 一致性。
  这是内核补丁，与"发行版内核即可"的约束冲突，而且每个内核版本都要重新适配。
- 内核其实已经有一条合法通道能读到 EPT A 位：mmu_notifier 的 `clear_young` 与
  `test_young` 回调。KVM 实现了这两个回调，内核在做页老化（`page_referenced`）
  时会调它们，把 EPT 的 A 位并入判断。page_idle 位图正是这条通道的用户态出口。

所以"读 EPT A 位"这件事本方案是做了的，只是经由内核已有的 page_idle 接口，
而不是自己改 KVM。

### 2.4 为什么不用宿主机页表的 A 位

`/proc/pid/clear_refs` 写 1 可以清进程页表的 Accessed 位，再从 pagemap 读回。
这套机制对普通进程有效，对 KVM 客户机**完全失明**：

- 客户机访问内存走 EPT，不走 QEMU 进程的页表。QEMU 页表的 A 位只反映 QEMU 自己
  线程（vCPU 线程在用户态、I/O 线程）对该页的访问，客户机跑了一小时，宿主机
  页表的 A 位可能一次都没置过。
- `clear_refs` 清位时不调 mmu_notifier，不会去清 EPT 的 A 位，读回时也不问 KVM。
- 同理，pagemap 的 soft-dirty 位也只跟踪宿主机页表写，看不见客户机写。

page_idle 位图不同：标记 idle 时内核对该页做 rmap 遍历，对每个映射调
`clear_young`，KVM 在回调里清 EPT 的 A 位；读回时调 `test_young`，KVM 回答
EPT 的 A 位是否又被硬件置上。**这是 page_idle 与宿主机页表 A 位的本质区别，
也是本方案能看到客户机读访问的原因。**

### 2.5 为什么不用 DAMON

DAMON 是内核自带的数据访问监控框架，它的 vaddr 与 paddr 两种原语都走
`ptep_clear_young_notify` 或 rmap，对 KVM 客户机是可见的。不选它的原因不在
信息源，而在工作方式：

1. **区域级而不是页级。** DAMON 把地址空间切成若干区域，每个采样周期（默认
   5 ms）在每个区域里随机挑一页看 A 位，用这一页代表整个区域，再按访问频率
   自适应拆分合并区域。它回答的是"这片几十 MB 到几 GB 的区域大致多热"，适合
   做粗粒度的 NUMA 迁移或 THP 决策。分层要决定的是"这一页能不能释放"，一个
   区域里哪怕 1% 的页是热的，整体换出就会制造上万次缺页。区域热度不能代替
   页级判断，拿到区域结论后仍然要对页逐个确认，等于白做一层。
2. **宿主机全局资源。** DAMON 经 sysfs 配置，每个监控上下文一个 kdamond 内核
   线程，以目标进程 pid 为单位。多台虚拟机就是多个上下文，由宿主机级进程统一
   配置，QEMU 自己管不了，和"按虚拟机策略、运行时可调"的模型拧着。
3. **常态开销。** DAMON 是持续采样的，没有内存压力也在跑，也在清 A 位制造 EPT
   aging。本方案只在允许换出时才扫描，没有压力时零开销。
4. **结果通道。** DAMON 的结果经 sysfs 或 tracepoint 输出，用户态轮询再解析，
   拿到的还是区域统计，没有"这一页冷"的直接结论。
5. **原设计里 DAMON 的位置。** 早期设计把 DAMON 当粗粒度 oracle，先用它圈出冷
   区域，再用 page_idle 细扫确认（三层漏斗）。实现后发现 page_idle 批量扫描
   一次就能给整个区域一致的秒级快照，第一层筛选没有必要，DAMON 一直没有接。
   `cell_heat` 字段至今是预留。

### 2.6 为什么写保护只做回退

userfaultfd 写保护是分层**已经在用**的机制，但只用在两处：换出窗口里判断页有
没有被改（§3.3），以及 page_idle 失效时的回退热度源。不拿它当主热度源的原因：

- **只看得见写。** 读热写冷的页（只读数据、代码、读多写少的缓存）会被误判为
  冷，换出后立刻被读回，形成换出换入抖动。
- **KVM 下读也会触发。** 实测把 39 万个换出页纯只读遍历一遍，产生了 39 万次
  WP 缺页。原因是 KVM 处理 EPT violation 时，只要 memslot 可写，就以写意图
  （`FOLL_WRITE`）去钉宿主机页，内核看到的是写缺页。所以"换入时写保护，再被写
  才算脏"这条路在 KVM 下走不通，换入后的第一次读就把写保护打掉了。swap-cache
  的干净判定因此改为换出时比对页内容哈希（§3.4）。
- **每次写一次 vCPU 停顿。** 一次 uffd WP 缺页约 10 µs，包含上下文切换到 fault
  线程再切回来。做热度源意味着每个候选页的每次首写都付一次，写密集负载上
  可观。SOSP'26 的 bpf_fault 把这一跳压到 1.6 µs，但它未进主线、与 uffd 互斥、
  自身不能做 I/O，评估见 `memtier-bpf-fault-assessment.md`。

### 2.7 当前方法：page_idle 批量扫描

**一次扫描做三件事：**

1. 用 `/proc/self/pagemap` 把区域内连续的虚拟地址批量翻译成物理页框号。
   连续虚拟地址对应连续的 pagemap 条目，一个区域几次大块 `pread` 就够。
2. 对 `/sys/kernel/mm/page_idle/bitmap` 做一次批量读。读到的位是**上一轮**
   扫描设置的，仍为 1 的页就是整个轮间间隔内没有被访问过的页。
3. 重新置位供下一轮观察，但只写回有变化的 64 位字。每个被置位的页内核都要做
   一次 rmap 遍历加 mmu_notifier `clear_young`，KVM 在 mmu lock 下清 EPT 的 A 位，
   跳过未变化的字就只对本轮被访问过的页重新老化。

关键点是**调用内不睡眠**。早期实现是逐 2 MB 块标记、睡 100 ms、回读，冷页探测
速度只有约 6 MB/s，多 GB 的区域要几分钟扫一遍。现在观察窗口就是两轮扫描之间的
间隔，一次批量最小 16 MB、最大 8 GB，批大小按"距常驻下限还差多少"换算，压力
下一拍就是整个区域一张近同一时刻的一致热度快照。

**两级去抖加冷却：**

```
每轮扫描
  │
  页级：idle_streak[页]++，一旦被访问清零
  │     连续 idle-streak 轮（默认 2）都空闲才算冷
  ▼
  2 MB 块级：本块有冷页 → cold_runs[块]++
  │     连续 cold-runs 轮（预设 2 / 5 / 8）都冷才允许换出，中途变热清零
  ▼
  候选页 = 冷 且 RESIDENT 且不在冷却期（cooldown-ms，换入或回滚后计时）
```

默认 idle-streak 为 2 的具体原因：换入的页会复用刚释放的物理页框，页框上残留的
idle 位会让它被误判为冷，形成"换入、立刻换出、再换入"的跑步机。要求第二次观察
才可信就消除了这个问题。cold-runs 在 2 MB 粒度抑制偶发波动，批量化后每轮覆盖
整批，去抖在几个窗口内收敛。

**扫描只在允许换出时跑。** 允许换出的条件是宿主机 PSI memory some avg10 达到
阈值、常驻量高于下限、后备有空间。宿主机没压力时 worker 每 200 ms 醒一次看
PSI 就睡，不碰位图。副作用是宿主机长时间空闲时冷页判定会陈旧，查询接口的
`scan-age-ms` 把这个暴露出来。

**自适应回退。** 某些情况下 page_idle 对客户机内存无效，所有页每轮都报"已访问"。
最常见的原因是开启分层前客户机内存已被 2 MB 透明大页背书，page_idle 只认 folio
头页，4K 粒度的位写不进也读不回。实现不做启动自检，而是行为自检：连续 30 个
窗口允许换出、余量充足却进展不足一个 2 MB 块，就单向切换到写老化回退并打
warn 日志。回退模式下所有在内存的页都是候选，冷热过滤转由换出窗口的写保护
回滚承担，代价是只看得见写热度。

**THP 陷阱已闭环。** 开启分层时暂停 vCPU，按 `/proc/kpageflags` 识别已有的 THP
块，拷出、释放、按 4K 回填，6 GB 客户机秒级完成。实测 THP 开启的客户机也能
拿到不分层基线的 91%，与关闭 THP 等效。例外是 vhost、VFIO 这类绕过 QEMU 主
循环的外部写入者，仍需关闭 THP。

### 2.8 当前方法的好处

- **读写都看得见**，4K 精度，这是对内核 swap 之外所有用户态方案最大的优势。
- **不改内核不改 KVM**，只用 CAP_SYS_ADMIN 开两个 proc/sysfs 文件。
- **稳态零开销**。RESIDENT 页的访问路径上没有页表陷阱、没有采样钩子、没有写
  保护。写保护只在换出窗口内短暂存在。
- **一致快照**。整个区域在同一轮里被判定，去抖以轮为单位，秒级收敛。
- **按虚拟机独立**。扫描范围、节奏、阈值都是区域（虚拟机）级参数。
- **退化有路**。page_idle 失效不致功能失效，只是热度源变差。

### 2.9 资源占用

**内存。** 每页元数据：状态与 slot 4 字节、换出 epoch 4 字节、换入时间戳 4 字节、
idle 连击 1 字节、换入位图 1 位，合计约 13 字节每页。32 GB 客户机约 100 MB。
换入过的页另存 16 字节 MurmurHash3 指纹（swap-cache 用），只对换入过的页分配。
主动换回的召回环最多 400 万条目、32 MB。I/O 缓冲固定：换入 64 个 4K bounce，
换出零拷贝不占缓冲。

**线程。** 每个区域一个 worker 线程加 1 到 8 个 fault 线程。worker 空闲时 200 ms
一拍，活跃换出时连续运转。fault 线程有换入在途或距上次活动 200 µs 内忙轮询，
否则睡在 `poll()`。SPDK 模式下换入线程独占一个核忙轮询。

**扫描的内核开销。** 批量化后用户态部分很小，大头在内核：每个被重新置位的页一次
rmap 遍历加一次 KVM EPT aging（mmu lock 下）。实测扫描自由运行时并发 vCPU 的
缺页 p99 从 55 µs 升到约 900 µs，原因是 EPT aging 与缺页处理争 mmu lock。
因此最小批量的扫描之间强制至少 200 ms 间隔，大批量排水不限速（本来就一拍完成）。

**换出的 I/O 占用。** 顺序写，受 `max-evict-mbps` 滚动窗口限速，预设 200 / 500 /
1000 MB/s。每次写 8 页（32 KB）：NVMe 没有抢占，缺页的 4K 读落在一个大写中间
要等写完，在写慢的介质上 512 KB 写会让碰撞的读等 3.5 ms，32 KB 只等 220 µs。
从 128 页 QD16 改为 8 页 QD1 后，最坏抖动下换入 p99 从 800 µs 降到 265 µs。
写快的设备不敏感。

### 2.10 对虚拟机的影响

按状态分：

| 客户机在做什么 | 影响 |
|---|---|
| 访问 RESIDENT 页（稳态） | 零。EPT 直通，无陷阱 |
| 扫描进行中访问任何页 | 被重新老化的页 EPT A 位被清，下次访问多一次 TLB 填充；与缺页争 mmu lock 的尾延迟已靠 200 ms 节奏压住 |
| 写一个正在换出的页 | 一次 WP 缺页约 10 µs，立刻放行，该页本轮换出作废 |
| 换出完成释放页 | 每 8 页一次 `MADV_DONTNEED`，一次 EPT zap 加 TLB shootdown；早期每页一次时换出突发是 vCPU 核上的 IPI 风暴，是换入 p99 的主要来源，批量后消除 |
| 访问已换出的页 | 一次缺页换入：消费级 NVMe 约 100 µs，Optane 加 SPDK 加绑核约 20 到 30 µs；多 vCPU 并发缺页流水线重叠 |
| 访问从未碰过的页 | 一次零填充缺页，约 10 µs |

整机数据（8 vCPU、8 GB redis，2:1 超分，Optane）：

- 均匀随机访问（无局部性，最坏情况）：吞吐为不分层基线的 15% 到 21%，p99 约
  6 到 10 ms。这是纯缺页路径的代价，与内核 swap 比平均吞吐低 34%（swap 在 vCPU
  自身上下文同步完成缺页、有簇预读），但最大延迟低 6 倍（137 ms 对 826 ms），
  因为分层的换出在后台线程，客户机线程从不参与回收。
- 热集负载（500 MB 热集装进 4 GB 常驻）：完全收敛后 98.5% 基线，p99 0.34 ms，
  与内核 swap 持平且 SET 最大延迟 18.6 ms 对 245 ms。
- 收敛需要时间：热集驻留与冷页判定要数百万请求积累，写突发后需 200 到 400 万
  请求重新收敛。

选型结论：热集明显小于常驻下限的业务（办公、Web、开发测试）可以 2:1 到 3:1；
数据库缓存类 1.2:1 到 1.5:1；全内存随机访问的负载不超分。

## 3. 换出

### 3.1 什么时候换

四个条件同时满足才换：

1. 宿主机 PSI memory some avg10 ≥ `psi-trigger`（预设 20 / 10 / 2%）。分层是
   压力响应式的，不是常态搬运。
2. 常驻量 > `min-resident-mb`（预设为总量的 75 / 50 / 25%），加 `hysteresis-mb`
   作为起动点。
3. 热度信号可用（page_idle 正常或已回退）。
4. 后备有空闲 chunk。满了发 `MEMTIER_BACKING_FULL` 事件并放弃本轮。

速率由 `max-evict-mbps` 滚动窗口限制。这四条都是区域级参数，宿主机级控制环按
虚拟机优先级与全局余量运行时下发。

### 3.2 页状态机

```
RESIDENT ──worker 选中冷页，置状态 + 加写保护──▶ EVICTING
EVICTING ──客户机写 → WP 缺页，标脏并立即解除写保护──▶ EVICTING_DIRTIED
EVICTING ──写盘完成且干净，锁内释放物理页──▶ SWAPPED
EVICTING_DIRTIED / 写失败 ──回滚，解除写保护，进入冷却期──▶ RESIDENT
SWAPPED ──客户机访问 MISSING 缺页，或主动换回选中──▶ FAULTING_IN
FAULTING_IN ──读回 + UFFDIO_COPY，唤醒 vCPU──▶ RESIDENT_CLEAN（保留 slot）
RESIDENT_CLEAN ──再被选中换出，哈希未变──▶ SWAPPED（不写盘）
RESIDENT_CLEAN ──哈希已变──▶ 写回原 slot ──▶ SWAPPED
SWAPPED ──压实搬迁 slot──▶ SWAPPED_MOVING ──▶ SWAPPED
```

所有状态转换在 1024 个按页号取模的分片自旋锁下进行；写保护是换出路径与客户机
写之间唯一的同步原语；换出状态机单线程化在 worker 里。

### 3.3 一次换出的流程

1. **切 run。** 把冷页图切成最大连续候选段（冷、RESIDENT 或 RESIDENT_CLEAN、
   不在冷却期），每段最多 8 页。
2. **分配 slot。** 从分块循环日志分配器拿连续 slot（§3.5）。
3. **逐页锁下置 EVICTING。**
4. **一次 ioctl 对整段加写保护**，含 TLB 冲刷。
5. **分类。** 读页内容：全零页标记零页消除；RESIDENT_CLEAN 页重算 128 位哈希与
   换入时记录的比对，相同标记"干净未变"，不同标记"写回原 slot"。
6. **一条大 SQE 零拷贝写。** 以客户机内存为源、O_DIRECT 直接写到连续 slot，
   换出侧因此是顺序写。零页和未变的干净页不在写集合里。
7. **等完成，再逐页裁决**，全部在锁内：
   - 仍是 EVICTING 且写成功：置 SWAPPED，记 slot 与换出 epoch。
   - EVICTING_DIRTIED 或写失败：回滚为 RESIDENT，解除写保护，归还 slot，
     写入冷却时间戳，`evict-aborts` 加一。
   - 零页：状态回 RESIDENT 但没有 slot，物理页照样释放。再访问时 fault 线程
     看到"RESIDENT 却不在内存"，给一个零页。
8. **一次 `MADV_DONTNEED` 释放整段连续的已换出页**。内核经 mmu_notifier 让 KVM
   zap 对应 EPT 表项，一次 TLB shootdown 而不是每页一次。

**为什么释放必须在锁内。** WP 缺页处理器的动作是"标脏、无条件解除写保护、放行"。
如果先在锁内置 SWAPPED、解锁、再释放页，中间那个窗口里一个被写保护拦住的客户机
写会被放行并落到即将丢弃的页里，释放把这次写连页一起丢掉，数据丢失。释放放在
锁内后，缺页处理器只能在页已经消失之后才观察到 SWAPPED，它的"解除写保护加唤醒"
让被拦的写重新触发，这次是 MISSING 缺页，走换入，写在换入完成后重放。

### 3.4 减少写盘量的三项措施

分层最大的隐性成本是 NVMe 寿命。4K 随机写放大加上冷热页来回搬运，一块消费盘
可能几个月写穿。三项措施（实测合计比基线少写 24%，细节见 `memtier-nvme-wear.md`）：

- **零页不落盘。** 分类时发现全零的页不写，释放后再访问给零页。redis 灌满的客户机
  零页只有 7.5%，普通客户机空闲内存多，比例高得多。
- **swap-cache。** 换入的页保留它的 slot，状态 RESIDENT_CLEAN，换入时记 16 字节
  MurmurHash3 指纹。再被换出时重算指纹，相同就直接置 SWAPPED 复用原 slot，零 I/O；
  不同则写回原 slot，不申请新 slot。这就是内核 swap"干净页直接丢弃"的等价物。
  原设计靠换入时写保护判脏，因 §2.6 说的 KVM 读写不分问题改成了比内容；再先做了
  读回逐字节比对，干净页换出从零 I/O 变成一次 70 µs 读，redis SET 吞吐掉 25%，
  才改成哈希。
- **分块循环日志分配器。** 后备按 2 MB chunk 组织成循环日志，换出总是在当前
  chunk 尾部追加，98% 的写落在上一次写的紧后面，对 SSD 的 FTL 最友好。整个
  chunk 的页都死掉就 discard 回收；空闲只剩两个 chunk 时压实最稀疏的 chunk
  （存活 ≤ 1/4），把存活页搬到新位置，被搬的页在 SWAPPED_MOVING 状态下短暂
  挡住并发缺页。

### 3.5 后备空间

- 文件或裸块设备，O_DIRECT 打开，或经 vfio-pci 交给 SPDK 用户态驱动。
- slot 29 位，上限 2 TB。预分配文件与裸盘性能无差异（实测）。
- 后备可靠性即虚拟机可靠性：换入读失败是致命错误，页内容此刻只在盘上。
  生产应用带冗余的卷。

## 4. 换入

### 4.1 被动换入（主路径）

```
vCPU 访问 SWAPPED 页 → EPT violation → KVM 发现宿主机无映射 → uffd MISSING 缺页
→ fault 线程收到消息（一次批量最多 64 条）
→ 锁下 SWAPPED → FAULTING_IN，取 slot
→ 提交 io_uring 读到注册的 bounce 缓冲（同批只 submit 一次，最多 64 路在途）
→ 完成后 UFFDIO_COPY bounce → 客户机页：原子建立映射，唤醒所有停驻在该页的 vCPU
→ 锁下置 RESIDENT_CLEAN，保留 slot，记哈希，写入冷却时间戳
```

按状态分派：

- SWAPPED：置 FAULTING_IN，提交异步读。
- FAULTING_IN 或 SWAPPED_MOVING：已有并发填充或压实在搬，直接返回。那次 COPY
  或压实完成后的 UFFDIO_WAKE 会一并唤醒本 vCPU。并发缺页天然串行化，无重复 I/O。
- 其他（从未填充，或零页消除释放的）：`UFFDIO_ZEROPAGE` 给零页。启动后从未触碰的
  内存不占后备空间。

延迟分解（消费级 NVMe 实测样本）：排队 9 µs、设备 85 µs、发布 6 µs。设备延迟
是大头，所以介质决定上限：Optane 比消费级 NVMe 快 3.3 倍，与 4K 读延迟之比一致。

软件路径上的优化，按收益排序：

- **流水线。** 每个缺页占一个 bounce，多 vCPU 并发缺页的盘读重叠执行。早期实现
  是提交一个等一个，16 个缺页 16 次串行往返。
- **自适应 busy-poll。** 有换入在途或距上次活动 200 µs 内，fault 线程自旋轮询。
  睡在 `poll()` 里每次缺页要多付两次调度唤醒，这是非 I/O 开销的大头。
- **fault 分片。** `fault-shards` 1 到 8，按地址分片的多 fault 线程，缓解单线程
  串行所有 vCPU 缺页的问题。单线程实测约 20 万缺页每秒。
- **SPDK。** 绕过内核块层、中断、io_uring 唤醒，每次缺页省约 20 µs 软件开销。
  Optane 上单独 +7%，加 vCPU 1:1 绑核与 fault 线程独占核后合计 +45%，p99 降 33%。
  消费级 NVMe 上器件延迟占绝对大头，SPDK 只有 +4%。
- **换入后冷却。** `cooldown-ms` 内不可再被选为换出候选，防止乒乓。

### 4.2 一次失败的尝试：簇预读

内核 swap 缺页时一次读回 8 页邻居。照搬到分层（缺页时把盘上相邻、仍 SWAPPED 且
slot 连续的页一次大读回来）实测吞吐掉 4 倍、缺页数翻倍，已回退。原因是**双重付费**：
内核的预读页进 swap cache，没用到就零成本丢弃；分层当时的预读页被 COPY 成完全
RESIDENT，常驻下限顶着时 worker 必须把这些没用到的页再写回盘，一次读加一次写
全浪费，每个真实缺页诱发约 7 个投机页的换出写。

swap-cache（§3.4）补上了"干净页零成本丢弃"这个前提。现在预读的页未被改过时，
再换出只是置状态加释放，不写盘。预读因此可以重新评估，但尚未重做。

### 4.3 主动换回

被动缺页之外，宿主机空闲时可以把最近换出的页提前拉回，削减后续缺页的尾延迟。

- **召回什么。** 一个按区域大小的召回环记录换出顺序，从最新端往旧端走，最近被
  换出的优先。理由是"最近被迫换出的页最可能是其实还在用、被压力误伤的"。条目
  时效 25.6 秒（256 个 100 ms epoch），比宿主机级控制环 5 秒的节拍长得多。
- **两道门。** 常驻量 < `target-resident-mb`，且宿主机 PSI < `swapin-watermark`。
  引擎强制 `swapin-watermark < psi-trigger`，换出在 PSI 高时触发、换回在 PSI 低时
  触发，在 PSI 轴上永不相交，不会振荡。默认 target = min，即不主动换回。
- **执行。** 独立的 io_uring 环与缓冲，不碰 fault 线程的资源，受
  `max-swapin-mbps` 限速。置 FAULTING_IN 后填充失败必须恢复 SWAPPED 并
  UFFDIO_WAKE，否则看到 FAULTING_IN 而停驻的客户机缺页会永远挂住。
- **与被动撞同一页。** 被动看到 FAULTING_IN 就等，主动那次 COPY 同时完成两件事；
  反向主动看到非 SWAPPED 就跳过。
- **谁决定回血。** 单台虚拟机看"宿主机空了"是局部视角，那块空闲可能要给别的
  虚拟机。QEMU 只暴露"换回到 target"的机制，回不回、回多少由宿主机级控制环
  按全局余量与优先级通过 `target-resident-mb` 下发。

实测 4 GB 换出到约 750 MB 后回血到 target 3000 MB，`active-swapins` 流式升到
45 万，1.77 GB 召回，常驻回升无抖动。

### 4.4 热度在换出后就冻结

页进 SWAPPED 后不在 RAM 里，page_idle 和任何 A 位都失效，没有访问事件可以更新
热度。所以换出瞬间打一个快照（epoch）存下，之后不动。真正反映"现在还热不热"
的唯一可靠信号是客户机来踩它。主动换回只是用快照做有根据的预测，猜错了由被动
兜底，多走一次读而已。快照不必精确，够区分新旧即可。

## 5. 迁移

### 5.1 不做集成时的问题

热迁移把客户机 RAM 经网络发到目的端。已换出的页在源端不在 RAM 里，有三种处理：

1. 迁移前 `x-memtier-disable` 把所有换出页读回 RAM 再迁移。简单可靠，但收敛时间
   与换出量成正比（实测 3 GB 换出页从消费级 NVMe 读回 91 秒），而且要求源端有
   足够 RAM 装下整台虚拟机，这与超分的初衷冲突。
2. 迁移流读到 SWAPPED 页时触发换入再发送。等价于把整个后备读一遍再过网络，
   两倍 I/O，并且这些冷页到目的端后全部变成常驻，目的端立即面对一台"全热"的
   虚拟机。
3. 后备是共享卷时不搬这些页。这就是当前的集成。

### 5.2 共享后备迁移（已实现）

前提：后备是源端与目的端都能打开的同一个卷，开启 `memtier-shared-backing`
迁移能力。

```
源端 位图首次同步前：进入迁移态
  worker 排空在途换出，EVICTING 全部回滚；此后不再换出、不 discard、不压实
  每页稳定为 RESIDENT / RESIDENT_CLEAN / SWAPPED
源端 位图同步后：清除所有 SWAPPED 页的脏位（它们不会被发送）
源端 首轮前：把热页的脏位暂存（§5.3）
源端 第 1 轮：只发冷的常驻页
源端 后续轮：普通脏页 precopy，含热页与迁移期间换入的页
源端 stop-copy：RAM 之后追加 "memtier" 节 {区域 id, 后备路径, 策略, 页数, [gfn, slot]...}
目的端 载入该节：打开同一共享卷，校验每对 (gfn, slot)，置 SWAPPED、保留 slot、
  MADV_DONTNEED 释放页，注册 uffd，启动 worker 与 fault 线程
目的端 客户机首次访问换出页 → 缺页 → 从共享卷按需读回
源端 直到 VM 再次 RUNNING 才解除迁移态
```

要点：

- **不变式**是"位图同步与清脏位之间不得有页变为 SWAPPED"，所以迁移态在位图
  首次同步之前就进入。迁移期间客户机缺页换入的页会重新标脏，后续轮当普通脏页发。
- **目的端在 VM 尚未运行时恢复状态**，然后天然继续处于分层状态，常驻量与源端
  一致，不需要重新收敛。
- **停机时间与换出量无关**。stop-copy 只多一个 12 字节每页（gfn 8 字节加 slot
  4 字节）的映射表，8 GB 客户机换出一半也只有 12 MB。
- **解除迁移态要等 VM RUNNING**。迁移到文件（内存快照）会让源端停在 postmigrate
  等编排层拷贝后备文件，这时若放开 worker，一次主动换回释放的 slot 可能被后续
  换出复用，破坏快照引用的后备。快照的两种恢复方式见
  `memtier-snapshot-restore-design.md`。
- 迁移期间换出被挂起，源端内存压力会上升，迁移时间长时需要控制环给源端留余量。

### 5.3 基于内存热度的 precopy 优化

精典 precopy 的浪费在于：首轮把所有页发一遍，热页在首轮之后又被写脏，后续轮
再发一遍甚至多遍，写密集负载可能永不收敛。减少浪费的办法是**首轮跳过会被重新
写脏的页**，让它们只在后面的轮次发一次。这需要一个"哪些页会被重新写脏"的预测，
分层本身就是热度源。

当前实现的信号：

- **热页** = 常驻且最近 4 秒内被换入或在换出窗口里被写回滚（`fault_tick`）。这两
  种事件都说明客户机刚碰过它，对"会不会被重新写脏"来说写热正是要的信号。
- **冷页** = 其余常驻页。它们在 idle 扫描里连续多轮无访问才会成为换出候选，
  没来得及换出的就是首轮要发的。
- 首轮把热页的脏位暂存不发，首轮结束后恢复，热页随后续轮走。

可以进一步做的（按收益排序，均未实现）：

1. **用 idle 连击做发送顺序。** `idle_streak` 与 `resident-cold-bytes` 已经按页
   区分"判冷未换出"和"热"。把 precopy 首轮按 idle 连击从高到低排序，最冷的先发，
   最热的最后发，热页在首轮尾部才发，被重新写脏的窗口最短。这比"4 秒内碰过"
   的二值判断细得多，而且对没有换出活动的虚拟机也成立。
2. **迁移前降级（demote-before-migrate）。** 迁移前先把判冷未换出的常驻页主动
   换出到共享卷，缩小要过网络的集合。换出是顺序写，预设上限 1 GB/s，通常比网络
   便宜；目的端得到的是一台与源端热度分布一致的虚拟机。这是快照里 demote-all
   选项的迁移版。
3. **目的端预热。** 源端把召回环（最近换出顺序）随 memtier 节一起发过去，目的端
   在 VM 启动后用主动换回按这个顺序预拉，削平切换后的第一波缺页。
4. **非共享后备。** 本地 NVMe 做后备时，可以把后备文件的已用 chunk 作为块设备
   流随迁移发送（drive-mirror 风格），或在目的端重建：源端迁移态冻结 slot 分配后，
   已换出页的内容在盘上是稳定的，按 chunk 顺序读发比按页缺页读发便宜一个数量级。
5. **对不开分层的虚拟机复用热度源。** page_idle 批量扫描不依赖分层的其他部分，
   迁移开始时对 RAM 做两轮扫描就能得到冷热图，用于首轮排序。代价是迁移期间的
   EPT aging 开销，需要同 §2.9 的节奏控制。

### 5.4 Post-copy 的位置

共享后备迁移在效果上已经是"冷页 post-copy"：冷的已换出页在目的端按需从共享卷
拉。它比网络 post-copy 好的地方是不依赖源端存活，源端可以立刻释放；差的地方是
只覆盖已换出的页。QEMU 原生 post-copy 可以和它叠加，用于热页的尾部，当前没有
测试过两者组合。

## 6. 限制

- 仅 4K 页。区域强制 `MADV_NOHUGEPAGE`，与大页后端互斥；开启时自动拆已有 THP，
  但 vhost、VFIO 等外部写入者场景仍需关 THP。
- 与 vhost-user 共享内存后端互斥，分层只作用于匿名内存。
- 单页换入读失败即 VM 退出。
- 非共享后备时热迁移与快照应先 disable 收敛。
- 后备上限 2 TB。
- 没有接 KVM async page fault，缺页期间 vCPU 硬停驻。
- 主动换回只按"最近换出"召回，没有按访问模式预取；簇预读待在 swap-cache 之上重做。
- 宿主机长时间无压力时冷页判定陈旧，监控需看 `scan-age-ms`。
- QAPI 接口带 `x-` 前缀，不承诺稳定。

## 附录 A. 名词

| 名词 | 含义 |
|---|---|
| EPT / NPT | Intel / AMD 的二级页表，客户机物理地址到宿主机物理地址 |
| A/D 位 | 页表项的 Accessed / Dirty 位，硬件在访问 / 写时置位 |
| page_idle | `/sys/kernel/mm/page_idle/bitmap`，按物理页框号索引的空闲位图 |
| mmu_notifier | 内核通知 KVM 等二级页表使用者"宿主机页表变了"的回调链 |
| userfaultfd | 用户态接管自己内存缺页处理的接口，MISSING 与 WP 两类事件 |
| PSI | Pressure Stall Information，`/proc/pressure/memory` 的内存压力指标 |
| DAMON | 内核的数据访问监控框架，区域级采样 |
| slot | 后备上的一个 4K 位置 |
| chunk | 后备分配器的 2 MB 单位，循环日志的基本单元 |
| run | 一次换出写的连续页段，最多 8 页 |
| epoch | 100 ms 一跳的粗时间戳，用于换出近度 |
| swap-cache | 换入后保留 slot、再换出时内容未变就不重写的机制 |
| precopy | 迁移时 VM 运行中迭代发送脏页，最后短暂停机发剩余 |
