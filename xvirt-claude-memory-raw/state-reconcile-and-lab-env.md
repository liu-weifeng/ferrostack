**State-reconcile fix (2026-06-13)**: standalone/compute ferrovirt previously only updated `vm.state` from live `vm.state_changed` events → after a power-loss reboot no QEMU runs, no shutoff event fires, DB stays `running` forever. `sync_one_host` only works for center-enrolled nodes (needs `sync_token`). Fixed by **ferrovirt actively pulling real state**: new `service/state_reconcile.rs::reconcile_host_states` (called in `host_manager::connect_host` startup + `reconcile_loop` every 60s) asks the agent action `list_vm_states` (lictor `controller/vm.py`, proxied by hyper-agent) for actual power state per DB uuid (QMP query-status / `_vm_qemu_alive` /proc scan / else shutoff) and `mark_*` on mismatch; `list_datastore_states` (hyper-agent storage) for FS-mount status. `event.rs` now persists `vm.guest.state` → `vm_guest_state` + `vm.ip/tools_status`. See CLAUDE.md 工作进展 2026-06-13. Related: [[ferrovirt_status]] [[dev-box-bringup-state]].

**State-drift-under-load fix (2026-06-19, committed lictor `2da50b9` + ferrovirt `55eadf6`, pushed)**: under heavy host load a *running* VM could drift to `shutoff` in the DB. Traced end-to-end: a healthy VM's QMP connection spuriously **EOFs** during a concurrent op → lictor `monitor/manager._on_conn_close` → its `_vm_qemu_alive` guard (a hand-rolled /proc walk) **false-negatives** under churn → publishes `vm.state_changed=shutoff reason=qmp_closed` AND/OR `list_vm_states` reports shutoff for the now-not-attached VM → reconcile flips DB. Load amplified by **stale `/var/lib/libvirt/qemu/domain-*/monitor.sock` dirs** (not cleaned on VM delete) that `scan_and_reconcile` thrashes on. Fixes: (1) `_vm_qemu_alive`→`pgrep -af <uuid>` (atomic, was racy /proc walk) + new `_qmp_sock_connectable` (connect the monitor.sock = authoritative); (2) `_on_conn_close` guard retries both probes w/ backoff before shutoff; (3) `list_vm_states` uses the combined probe; (4) ferrovirt reconcile **hysteresis**: 3 consecutive shutoff reports before flipping running→shutoff (running/paused resets). Drift gone under real autotest load; only survives deliberately-extreme 3-thread create/delete churn (non-real). **Stale domain-dir cleanup on delete FIXED** (hyper-agent `c512074`): `delete_vm` now rmtrees `/var/lib/libvirt/qemu/domain-<uuid>/` (monitor.sock) + `/run/libvirt/qemu/channel/<uuid>/` (guest-agent/xvt sockets) — these are pure transient (UEFI NVRAM is elsewhere); leaving them made lictor's `scan_and_reconcile` retry-attach to dozens of dead socks each cycle (the load amplifier). Residual unfixed: the spurious QMP EOF itself (needs QEMU-side dig); stopped-but-not-deleted VMs still leave a stale monitor.sock until started/deleted (minor — the delete cleanup handles the bulk accumulation).
