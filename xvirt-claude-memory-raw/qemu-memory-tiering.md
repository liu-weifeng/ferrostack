The xvirt qemu fork (`/root/code/xvirt/qemu`, remote `ssh://git@192.168.2.107:2222/liuwfng/qemu.git`) has a **`memory-tiering`** branch (HEAD `8651cbfb23` as of 2026-06-03), a strict superset of `stable-10.0-dev` + a `memtier/` subsystem: hot guest pages stay in host RAM, cold pages evicted to a backing block device via **userfaultfd-wp + io_uring** (KVM unmodified; uses mmu_notifier). Design doc: `docs/devel/memory-tiering.rst` (+ `liuwfng/qemu-memory-tiering-full-design.md`).

**QMP (experimental `x-`):** `x-memtier-enable {path:<backing raw dev/file>, *policy:conservative|balanced|aggressive, *tunables}`, `x-memtier-query` (→ resident/swapped/evicted-pages/swapin-faults/swapin-errors/evict-aborts/psi-some-avg10...), `x-memtier-set-policy`, `x-memtier-disable` (forces every swapped page back, then tears down). Targets the main guest RAM block by default. Tunables: cold-threshold, cold-runs, psi-trigger, max-evict-mbps, min-resident-mb, cooldown-ms.

**Build the deb:** `cd build-deb && ./build_deb.sh ../qemu memory-tiering` → debs in `build-deb/out/*+git<sha>*.deb`. The deb's `debian/rules` already has `--enable-linux-io-uring`; `liburing-dev` is installed on the dev host, so memtier compiles the real impl (else `memtier-stubs.c`). Install: `dpkg -i` the full matching `+git<sha>` set together (system-x86 + common + data + modules-* + utils + block-extra). **The dev host currently runs this memtier build (`8651cbfb23`)** — it's a superset so all petrel/aegis/hotness features still work; revert by reinstalling the `stable-10.0-dev` debs if needed.

**Testing gotcha — force eviction without host pressure:** eviction only runs when host PSI memory `some avg10` ≥ `psi-trigger` AND resident > `min-resident-mb`. The dev host has ~27 GB free → PSI≈0 → nothing evicts. Set tunable **`psi-trigger: 0`** (PSI is read from global `/proc/pressure/memory` in `memtier/memtier.c`) + low `min-resident-mb` to force eviction. Needs `CAP_SYS_ADMIN` at runtime (root) for `/proc/self/pagemap` + `/sys/kernel/mm/page_idle/bitmap`. Target RAM must be anonymous (plain `-m N`, NOT memory-backend-memfd) — so a petrel VM (memfd shared mem) is not a valid memtier target.

**INTEGRATED into xvirt — opt-in at VM create** (2026-06-03, ferrovirt `2bf240d`, hyper-agent `98f953c`, lictor `cb750cb`, schema xvirt-top `98c093e`, all pushed): `POST /api/vcenter/vm` accepts `"memtier":{"enabled":true,"policy":"balanced|conservative|aggressive","path"?:<host dev/file>,"tunables"?:{...}}`.
- **ferrovirt** `vm_create.rs`: `complete()` carries memtier into the agent config; `persist_vm` stores it on `vm_config` (new cols `memtier_enabled`/`memtier_policy`/`memtier_backing_path` — ALTER existing DBs, in `ferrovirt-schema.sql` for fresh); rejects memtier + petrel disks (HTTP 400; petrel=memfd RAM vs memtier=anon RAM). `vm_update.rs` `regen_inner` re-emits memtier from DB on edit so the sidecar isn't dropped.
- **hyper-agent** `vm/guest.py`: `create_vm`/`update_vm` write `<vm_dir>/memtier.json` `{enabled,policy,path,tunables}`; if no `path`, `fallocate` `<vm_dir>/memtier-backing.raw` sized to guest RAM (holds 100% evicted). `_write_memtier_sidecar`.
- **lictor** `vm/guest.py`: `launch_vm` after cont+attach calls `_memtier_enable_on_start` → reads memtier.json → QMP `x-memtier-enable` (best-effort; skips if VM has petrel/memfd RAM).
- **Validated**: created `memtier-vm` (1 GiB, cfg-pool LVM, memtier balanced) via dev-host API → DB `memtier_enabled=1`, sidecar written, 1 GiB backing fallocated → started → QEMU (the memtier build) has **fd→memtier-backing.raw open + `memtier-fault`/`memtier-worker` threads** = `x-memtier-enable` fired. Negative test memtier+petrel → HTTP 400. Constraint: memtier VM must use anonymous RAM (no petrel disks). Backing file lives in vm_dir (removed with the VM).
- **Frontend** (xvirt-client `9b362d4`): New VM wizard Advanced section has a memtier toggle + policy dropdown (conservative/balanced/aggressive); `buildCreateRequest` emits `memtier:{enabled,policy}`; auto-disabled with a hint when any disk is on a petrel datastore (`hasPetrelDisk` guard, also gates the payload); shown in the review step. Deployed to `/usr/share/xvirt-client/dist`.
- **Stats display** (ferrovirt `64821b2`, lictor `787d553`, hyper-agent `357a338`, xvirt-client `b63c8a3`): `GET /api/vcenter/vm/{vm}/memtier` → `service::write::memtier_query` → agent `memtier_query` → lictor `GuestManager.memtier_query` (QMP `x-memtier-query`). Returns soft status `{configured, policy, running, regions:[MemTierInfo...], error?}` (no 4xx on stopped/unsupported). Frontend `VMMonitor` polls it every 5s and renders a "内存分层" card (only when `configured`) with a resident/swapped bar + KV (evicted-pages, swapin-faults, swapin-errors, evict-mbps, psi-some-avg10, backing used/total, path). Validated on a live xvirt-created memtier VM: endpoint returns the full region structure (idle no-OS VM → zeros, which is correct — nothing resident-and-cold to evict; real numbers validated separately).

**HOST-LEVEL CONTROLLER (Model A)** (2026-06-03, lictor `a8ad6f7`, hyper-agent `0d07984`, ferrovirt `e455294`, schema `92ede0e`): a single per-host control loop owns the global PSI response so N in-QEMU workers don't each react independently. **Lives in hyper-agent, NOT concilium** — tiering is host-local (host RAM + local backing + local QMP) and must keep working when the node is partitioned; concilium is cluster-scope (quorum/placement/HA, self-fences minority, deliberately doesn't touch QMP). concilium only gets a lifecycle touchpoint later (disable-before-migrate via the migrate RA).
- **hyper-agent** `support/memtier/controller.py`: daemon thread started in `shell.py` (like petrel-reconcile). Every 5s: scan `/datastore/*/<uuid>/memtier.json` for enabled VMs (+priority) → read host pressure (`/proc/pressure/memory` some avg10 vs `PSI_HIGH=10`, `MemAvailable%` vs `FREE_LOW_PCT=10`, combined 0..1) → per running VM (confirmed via lictor `memtier_query`) compute `decide(pressure,priority,total_mb)` → apply via lictor `memtier_set_policy`. **Owns psi-trigger**: no pressure → `psi-trigger=100`(pause)+full floor+64mbps; pressure → `psi-trigger=0`+`min-resident-mb`=floor (FLOOR_FRAC high .75/normal .5/low .25, scaled down by `EVICT_DEPTH=0.8*pressure`, MIN 64MiB)+evict-rate (low evicts faster). Priority falls back from policy preset (aggressive→low/balanced→normal/conservative→high). Env overrides: `XVIRT_MEMTIER_{INTERVAL,PSI_HIGH,FREE_LOW_PCT}`. The in-QEMU worker just executes within these bounds.
- **lictor** `memtier_set_policy`(QMP x-memtier-set-policy)+`memtier_disable`(x-memtier-disable) actions; hyper-agent forwards both.
- **ferrovirt**: `vm_config.memtier_priority` col (ALTER + schema); carried create/persist/regen; written into the sidecar (`priority`).
- **Validated E2E** on dev host: created memtier-ctl VM (priority=low, balanced) → started → background controller overrode the preset to its no-pressure decision (effective tunables psi-trigger=100/min-resident=1024/64mbps); a forced-pressure tick (monkeypatched `host_pressure→1.0`) against the live VM flipped it to psi-trigger=0/min-resident=64MiB/1024mbps; background loop re-asserted pause 8s later (proves continuous + authoritative). Full chain controller→lictor→QMP confirmed via `x-memtier-query` effective tunables. (Actual evicted-pages stay 0 on a no-OS VM — nothing resident-and-cold; real eviction numbers proven separately.)
- **Follow-ups**: wizard priority selector (UI); concilium migrate-RA disable-before-migrate; host memory budget config surfaced in ferrovirt/UI; model B (centralized evictor) if finer control needed.

**OVERSUBSCRIPTION CAPABILITY + real-time hotness / timely eviction fix** (qemu `9b694af481`, 2026-06-03): the original worker scanned ONE 2MB cell per ~200ms iteration (each with its own 100ms idle window, round-robin) → cold detection ~**6 MiB/s**; a 4GB VM **never reached 50% evicted in 4 min**. Also `max-evict-mbps` was parsed but never enforced and `evict-mbps` stat was always 0.
- **Fix** (`memtier/scan.c` + `worker.c` + `memtier-int.h`): `memtier_scan_range_cold()` scans a contiguous *range* of cells under ONE shared 100ms window (coherent real-time hotness snapshot); PFNs via bulk pagemap reads; page_idle marked/read via one **bulk RMW over the PFN word-span** (a few syscalls/batch instead of 2/page — the old cap), per-page fallback if span absurd. worker sizes the batch to gap-to-floor (`SCAN_CELLS_MIN=8`..`MAX=4096`) so under pressure it snapshots the whole region per iteration → `cold-runs` debounce resolves in ~2 windows (accurate, no thrash) not many round-robin cycles. Implemented evict-mbps stat + max-evict-mbps rolling-window throttle.
- **Measured** (4GB VM, 3GB workload, 256MB continuously-hot, aggressive, floor 512MB, on the local `qemu/build/qemu-system-x86_64`): eviction streams from ~6s, **>50% flushed at ~21s**, settles **resident 727MB / swapped 3368MB (~82% flushed)**; swap-in churn low (hot set preserved); **400MB swap-in integrity = byte-perfect sha256**; guest stayed live. (cold-runs=1 was ~16x more thrash — keep the aggressive preset's cold-runs=2.)
- **Iteration harness**: local focused build `cd qemu && ./configure --target-list=x86_64-softmmu --enable-linux-io-uring --enable-kvm --disable-docs --disable-tools --disable-werror && ninja -C build qemu-system-x86_64` (incremental relink ~30s); test = standalone `build/qemu-system-x86_64` on a node.qcow2 overlay + `/scratch/tmp/memhog.py` (hot-subset workload) + `/scratch/tmp/qmpdrive.py` (QMP enable/query/set-policy). Deploy to system/controller path = rebuild deb (`build-deb/build_deb.sh ../qemu memory-tiering`) + dpkg -i.

**CONTROLLER auto-compression under REAL host pressure — full integration E2E** (2026-06-03): xvirt-managed VM (`memtier-real`, 4GB, aggressive/priority=low, on cfg-pool) made bootable by overlaying node.qcow2 onto its disk file + injecting an auto-run `memhog.service` (qemu-nbd mount, no SSH); started via the REST API so lictor enables memtier at launch + the running hyper-agent controller discovers it via sidecar. Sequence, all driven by the controller (no manual QMP):
  1. No host pressure → controller **paused** (psi-trig=100, floor=full) while the guest filled ~3.6GB (host free 91%→79%).
  2. Real 12GB host hog → free 79%→**50%** (below the configured 70% threshold) → controller **immediately** set psi-trig=0 + floor≈700MiB → QEMU evicted → **resident 4096→~790MiB, swapped ~3300MiB (~81% flushed) in ~10s**, stable under sustained pressure.
  3. Released hog → free→89% → controller **eased back** to psi-trig=100/floor=full; swapped pages stay on disk (lazy return on access).
  - Confirms the whole stack: REST create (memtier) → lictor x-memtier-enable → hyper-agent controller reads REAL `/proc/meminfo` → lictor `memtier_set_policy` → QEMU batched-scan eviction. Threshold set via systemd drop-in `XVIRT_MEMTIER_FREE_LOW_PCT=70` (default 10 is conservative; restored after). Test harness: `/scratch/tmp/{memhog.py,hosthog.py}`; bootable xvirt VM = overlay node.qcow2 onto `/datastore/<seg>/<vm>/<disk>.qcow2` + nbd-inject a memhog systemd unit.

**PROACTIVE SWAP-BACK v1** (qemu `b588024dbd`, 2026-06-03; design `docs/memtier-heat-and-swapback.md`): latency optimization (prefetch recently-evicted pages back during idle to cut fault tail latency), **default OFF** (target==min), passive fault always backstops. `page_meta_t` 4B→8B (+`evict_epoch`); per-region epoch clock + `NR_BUCKETS=64`×`EPOCH_PERIOD_MS=100ms` ring of preallocated gfn buckets; `evict_complete_one` snapshots evict_epoch + bucket-inserts (O(1), no malloc-under-lock). `memtier_swapback_tick` (worker): target gate + PSI hysteresis gate (engine clamps `swapin-watermark < psi-trigger`), recall newest buckets first. `memtier_active_swapback` (fault.c): one page on a **dedicated swapback ring+bounce** (never the fault thread's), UFFDIO_COPY prefill wakes any parked fault, on read failure restores SWAPPED + UFFDIO_WAKE (no exit). QMP `MemTierTunables += target-resident-mb/swapin-watermark/max-swapin-mbps`; `MemTierInfo += active-swapins`. **Tested**: evict 4GB guest to ~740MB → flip to swap-back (psi-trigger=80, target=3000, watermark=40) → active-swapins 58424 (~228MB recalled, no guest access), resident↑/swapped↓ then plateau at the ~6.4s recency window (by design), no thrash, integrity PASS. **Deferred**: `evict_heat` (needs a cell-heat EWMA, not yet maintained — v1 recalls by recency only); bigger recall window for latency-sensitive; wire `target-resident-mb` into the hyper-agent controller for global "回血". Iteration: edit `qemu/memtier/*.c` → `ninja -C build qemu-system-x86_64` → standalone test with node.qcow2 overlay + memhog + QMP set-policy.

**SWAP-BACK: recall RING (not per-epoch buckets) + controller 回血 integration** (2026-06-03): the proactive swap-back recall structure was changed from NR_BUCKETS per-epoch buckets to a single recall RING (qemu `f11a9d3b9f`) because the batched evictor evicts GBs in one ~100ms epoch → per-epoch buckets (cap 8192) overflowed and swap-back recalled only ~64MB of a 1.7GB evicted set. Ring sized to region (cap `RECALL_RING_MAX`=4M entries/32MB), evict appends gfn (overwrites oldest), swap-back walks newest-first, validity=`SWAPPED && epoch-age<=RECALL_WINDOW_EPOCHS(256=25.6s)`, break on first aged entry. Also widened window 6.4s→25.6s (a 6.4s window was shorter than the external controller's ~5s cadence, so pressure-evicted pages aged out before 回血 was requested). **Standalone validated**: evict 4GB→~750MB then swap-back target 3000 → active-swapins streamed 160→453836 (~1.77GB recalled) vs ~16K with buckets.
- **Controller 回血** (hyper-agent `9807ca4`): `support/memtier/controller.py` now has two host water lines — `XVIRT_MEMTIER_FREE_LOW_PCT`(10, evict below) + `FREE_HIGH_PCT`(50, 回血 above), dead band between = passive only (no oscillation). `decide()` per regime: pressure→psi-trigger=0/min by pressure×priority/target=min; headroom→psi-trigger=100/target raised from min toward full by headroom×SWAPBACK_WEIGHT(high1.0/normal0.6/low0.3)/swapin-watermark=50; deadband→pause. Sends target-resident-mb/swapin-watermark/max-swapin-mbps via memtier_set_policy.
- **Controller E2E** (dev host, FREE_LOW=55/HIGH=60 test drop-in): hog→free60%→26%→controller psi-trig0/target↓→evict resident 2322→1825(+497MB swapped); release→free86%→controller psi-trig100/**target raised 1832→3739**→**active-swapins 16218→36623, resident↑, swapped↓** = controller-driven 回血 confirmed. Recall per controller cycle is partial (5s cadence vs recency window catches part of each burst + boot-spike baseline noise); full-window recall proven standalone. Latency optimization, passive backstops, default off (target==min).
